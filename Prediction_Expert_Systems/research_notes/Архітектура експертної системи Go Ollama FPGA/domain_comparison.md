# Domain comparison: Go, Ollama, and FPGA expert system

**Evidence snapshot: 2 November 2026.** The FPGA is unselected, and no deployment, jurisdiction, or safety classification is assumed. The LLM is treated as advisory; this comparison does not imply that it should issue or authorize safety decisions.

## Ranked comparison

| Rank | Domain | Reproducible public outcome | Main limitation |
|---|---|---|---|
| 1 | Industrial equipment prognostics | Simulated or measured run-to-failure endpoint; remaining cycles/time, tool wear, or fault label | Public benchmark scale and synthetic/accelerated conditions limit external validity |
| 2 | Energy infrastructure | Hourly demand and generation; forecast error | Public aggregate data generally do not label component degradation or failures |
| 3 | Automotive/embedded safety | Retrospective fatal-crash outcomes; some public vehicle datasets support perception labels | These labels do not establish embedded-system safety, hazard response, or real-time assurance |

**Recommendation:** begin with industrial prognostics, explicitly as a research demonstrator, not a production or certified safety function. It offers the most direct falsifiable prediction target. NASA’s repository lists FEMTO accelerated bearing tests, cutter wear data, and a second turbofan run-to-failure simulation. The latter is explicitly synthetic, based on C-MAPSS, and described as a small fleet under realistic flight conditions; time-to-trajectory-end can provide a reproducible RUL target in cycles or time. The older NASA C-MAPSS/C-MAPSS40K catalog page currently says those software packages are unavailable, while the repository separately lists a downloadable “Turbofan Engine Degradation Simulation-2” dataset. Treat this as a version/access distinction: freeze the exact archive, license, checksum, and labels before the protocol. ([NASA Prognostics Data Repository](https://www.nasa.gov/intelligent-systems-division/discovery-and-systems-health/pcoe/pcoe-data-set-repository/); [NASA C-MAPSS catalog](https://data.nasa.gov/dataset/c-mapss-aircraft-engine-simulator-data))

The PHM Society’s CNC milling challenge provides a more physical degradation task: six cutter records, dynamometer/accelerometer/acoustic-emission channels, and wear measurements in training records. Its documented split is only three training and three test cutters; the page flags an incorrect wear file for cutter 3, and test labels are not simply exposed as a ready-to-score public benchmark. It is therefore useful for an independent replication only after file verification and an explicit evaluation-label plan—not as the sole benchmark. ([PHM Society 2010 CNC challenge](https://phmsociety.org/phm_competition/2010-phm-society-conference-data-challenge/))

**Industrial measurable outputs:** predict RUL (cycles or hours), measured wear (e.g., mm), or a defined maintenance class (`MONITOR`/`INSPECT`). Use asset-level splits, never random row splits; report MAE/RMSE, lead time at a preregistered alert threshold, and the separate rates of late and unnecessarily early alerts. Compare against a simple persistence/linear-trend baseline. A public benchmark can falsify model accuracy and software behavior, but cannot prove field transfer, sensor integrity, or a safe maintenance policy. Maintenance decisions often allow a longer horizon than embedded control, but no decision deadline follows from these datasets; measure Go end-to-end latency on the actual board later. Do not let Ollama supply labels or override deterministic rules.

**Energy infrastructure ranks second.** EIA exposes an hourly grid monitor for demand and generation across U.S. balancing authorities, so a forecast task has time-stamped numeric targets and can be evaluated by chronological holdout using MAE/RMSE and a predeclared high-demand alert rule. This is a credible, accessible experiment for energy forecasting, not equipment prognostics: the public aggregate series does not identify a turbine, transformer, or protection-device degradation event. It also cannot support claims about sub-second protection latency. ([EIA electricity data and hourly grid monitor](https://www.eia.gov/electricity/))

**Automotive/embedded safety ranks third for the first experiment.** NHTSA’s Fatality Analysis Reporting System offers retrospective fatal-crash outcomes, which can ground a year-held-out crash-severity classification task. But crash records are not sensor streams or labels for an embedded controller’s safe/unsafe output; rare outcomes, selection effects, and absent real-time timing ground truth prevent a direct safety-system benchmark. NHTSA’s landing page returned HTTP 403 to this research retrieval, so current files and metadata need direct confirmation before use. ([NHTSA FARS](https://www.nhtsa.gov/research-data/fatality-analysis-reporting-system-fars))

## Assurance boundary and evidence gaps

Standards are conditional on what the system does, not on Go, Ollama, or FPGA alone. IEC 61508-1 describes requirements for E/E/programmable electronic systems performing safety functions; it is relevant only if this system is assigned such a role. ISO 26262 covers road-vehicle functional-safety lifecycle topics, and ISO/SAE 21434 covers vehicle cybersecurity engineering. Their public catalog pages establish scope and status, not conformance: normative text is sold/licensed, and a product’s hazard analysis, safety goals, ASIL allocation, security risk assessment, verification evidence, and safety case are organization- and deployment-specific. ([IEC 61508-1 catalog](https://webstore.iec.ch/en/publication/5515); [ISO 26262 package](https://www.iso.org/publication/PUB200262.html); [ISO/SAE 21434 catalog](https://www.iso.org/standard/70918.html))

No public dataset decides whether an advisory model is a safety-related function, whether it can influence an operator or actuator, which jurisdictional regulation applies, or what assurance level is required. Those are evidence gaps, not reasons to assume certification duties or to claim certification. The dataset sources also do not establish production latency, FPGA resource limits, LLM determinism, or cross-site generalization.

## Falsifiable domain-selection experiments

1. **Industrial RUL gate (recommended):** obtain and hash the exact NASA C-MAPSS-2 archive; split by complete engine trajectory; derive remaining cycles to the supplied run endpoint. Compare a frozen predictor/rule system with linear-trend and persistence baselines. Predeclare MAE/RMSE and late-alert rate at one maintenance horizon. If targets or splits cannot be independently reconstructed, stop the RUL claim; if the system fails the baseline or alert criterion, do not advance it as a prognostic demonstrator.
2. **Energy alternative:** use a fixed historical EIA hourly-demand window and chronological train/test split. Compare next-hour MAE against persistence and report high-demand alert recall at a threshold fixed before testing. Passing supports a grid-demand advisory experiment only; it does not support asset-health or protection claims.
3. **Automotive boundary test:** on FARS, freeze a year-held-out fatal-outcome classification protocol and report precision-recall/calibration against a prevalence baseline. If the intended claim requires embedded response, demonstrate separately that public crash data cannot validate sensor-to-decision latency or safe control; require a vehicle-specific dataset and hazard case before choosing this domain.

**Source set (8 central sources):** NASA Prognostics Data Repository; NASA C-MAPSS catalog; PHM Society CNC challenge; EIA electricity data; NHTSA FARS; IEC 61508-1 catalog; ISO 26262 package; ISO/SAE 21434 catalog. Each is linked above.
