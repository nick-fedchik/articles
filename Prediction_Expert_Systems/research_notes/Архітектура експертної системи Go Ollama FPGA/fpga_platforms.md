# Кандидатні ролі FPGA для експертної системи Go–Ollama

## 1. Класи FPGA та межі платформ

### Takeaway
Клас FPGA визначають місце даних і складність інтеграції. Мала мікросхема, SoC FPGA та PCIe-плата — різні способи під'єднати логіку до процесора, а не рівні прискорення.

### Cited Findings
- **Специфікація виробника:** Lattice вказує для малопотужного iCE40 UltraPlus до 5 тис. LUT. Це специфікація логічних ресурсів, не вимірювання готової плати. [Lattice iCE40 UltraPlus](https://www.latticesemi.com/Products/FPGAandCPLD/iCE40UltraPlus)
- **Специфікація виробника:** AMD Zynq-7000 поєднує Arm Cortex-A9 із програмованою логікою. Запуск Go на тому самому пристрої залежить від плати, ОС та архітектурної підтримки. [AMD Zynq-7000 Overview, DS190](https://docs.amd.com/v/u/en-US/ds190-Zynq-7000-Overview)
- **Документація інтерфейсу:** AMD описує PCIe DMA та AXI, Intel — окремий PCIe IP/інтерфейс. Це не гарантує сумісних драйверів чи API між платами. [AMD PG195](https://docs.amd.com/r/en-US/pg195-pcie-dma/Introduction); [Intel FPGA PCIe guide](https://www.intel.com/content/www/us/en/docs/programmable/683059/18-1/introduction-to-intel-fpga-pcie.html)

### Inferences
- **Кандидат:** малий FPGA — для невеликої фіксованої периферійної функції; SPI/GPIO та інші I/O залежать від плати.
- **Кандидат:** SoC FPGA підходить для локальної обробки сенсорних потоків через AXI; PCIe-карта — коли хост має слот і обсяг даних виправдовує DMA та складнішу інтеграцію.
- **Інтеграційна пропозиція:** Go не є готовим vendor SDK. Для PCIe потрібен драйвер/бібліотека через cgo або окремий сервіс; для SoC — драйвер Linux до AXI-периферії. Ethernet/SPI зменшують прив'язку до PCIe, але також додають затримки й протокольні вимоги.

### Gaps
- Без плати, смуги I/O, бюджету потужності, ОС і цінового ліміту неможливо зіставити конкретні ресурси чи вартість.

## 2. Придатні та непридатні частини експертної системи

### Takeaway
FPGA-кандидати — обмежені повторювані операції над потоком; змінні знання, нерегулярне виведення й генерація мови залишаються на хості, доки виміри не доведуть інше.

### Cited Findings
- **Виміряний результат, вузька задача:** FINN повідомляє до 12,3 млн класифікацій MNIST/с, затримку 0,31 мкс і менш як 25 Вт загальної потужності системи для бінаризованої мережі на ZC706. Це не прогноз для експертного рушія чи LLM. [FINN, FPGA 2017 paper](https://arxiv.org/abs/1612.07119)
- MLPerf Tiny вимірює точність, затримку й енергію в задачах від keyword spotting до anomaly detection; це методичний орієнтир, не прямий тест Go–Ollama. [MLPerf Tiny](https://arxiv.org/abs/2106.07597)

### Inferences
- **Перевірити:** потокову фільтрацію, FIR/віконні перетворення, фіксованоточкові ознаки, часові монітори зі скінченним станом і малий статичний набір булевих предикатів — якщо профіль CPU підтвердить вузьке місце.
- **Залишити в Go:** змінні правила, нерегулярний пошук фактів, оркестрацію, журналювання та оновлення знань, якщо профіль не знайде окремого стабільного обчислювального ядра.
- Результати FINN не доводять перевагу FPGA для загального LLM-виведення. Ollama варто залишити на CPU/GPU/NPU; оцінювати FPGA можна після фіксації моделі, квантування, контексту, пам'яті й вимог до точності.

### Gaps
- Без частоти потоку, розміру вікна, точності ознак, кількості правил і параметрів Ollama немає доказів зменшення повної затримки чи енергії.

## 3. Інтеграція, верифікація та життєвий цикл

### Takeaway
FPGA переносить частину оптимізації до апаратного проєктування: треба врахувати синтез, часовий аналіз, драйвери та відтворюваність.

### Cited Findings
- AMD та Intel документують PCIe DMA/IP; самі інтерфейси не усувають витрат черг, передавання й керування. [AMD PG195](https://docs.amd.com/r/en-US/pg195-pcie-dma/Introduction); [Intel FPGA PCIe guide](https://www.intel.com/content/www/us/en/docs/programmable/683059/18-1/introduction-to-intel-fpga-pcie.html)

### Inferences
- До витрат включити синтез і трасування, таймінг, драйвер, діагностику, еквівалентність, потужність, інструменти та відтворюваність bitstream. PCIe додає інтеграційні складнощі; SoC — залежність від BSP, Linux і плати.
- **Перевірка:** зафіксувати домен входів, арифметику, переповнення, порядок подій, межі черг та втрати. Симуляція й формальні властивості перевіряють логіку; часовий звіт не доводить end-to-end затримку через ОС, DMA, драйвер і Go-планувальник.
- Без WCET та незалежної перевірки не називати FPGA «жорстким реальним часом». Вимірювати повну потужність, LUT/DSP/BRAM, температуру, пропуски, затримки й версії інструментів.

### Gaps
- Жоден оглянутий результат не дає виміряних інтеграційних витрат саме для цієї системи, однакового тестового навантаження чи вартості підтримки її протягом життєвого циклу.
- AMD та Intel посилання ведуть на офіційні публічні портали, але під час перевірки вміст відображався лише як JavaScript-застосунок. Тому точні версії SDK, назви API та інструкції для драйверів тут не стверджуються; їх треба перевірити для обраної плати.

## 4. Справедливий порівняльний експеримент

### Takeaway
Порівнювати слід однакову функцію та повний шлях до рішення, а не пікову швидкість ядра. Метрики MLPerf Tiny треба адаптувати до експертної системи.

### Cited Findings
- MLPerf Tiny обґрунтовує набір метрик точності, затримки та енергії та модульне порівняння апаратних платформ. [MLPerf Tiny](https://arxiv.org/abs/2106.07597)

### Inferences
- Підготувати однакові записані/синтетичні потоки подій із мітками часу, граничними випадками й еталонними рішеннями. Окремо заміряти фільтрацію/ознаки, монітори, статичні предикати й повний Go-шлях; Ollama — як рівень із зафіксованою моделлю.
- Вирівняти точність, округлення, порядок подій і виходи CPU, GPU/NPU та FPGA; спершу перевірити еквівалентність. Звіт: пропускна здатність, медіана/p95/p99, енергія на рішення і вся система, втрати та transfer overhead; розрізняти час ядра й end-to-end.
- Зафіксувати плату, частоти, драйвери, компілятори, вимірювач, температуру, повтори й прогрів. FINN — приклад вузької задачі, не baseline для цієї системи.

### Gaps
- Поки немає вимірювань, не можна обрати плату чи заявити перевагу за швидкістю, енергією, вартістю або детермінованістю.
