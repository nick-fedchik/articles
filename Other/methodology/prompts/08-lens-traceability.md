# 08. Лінза T: трасування

**Мета.** Побудувати матриці трасування між рівнями вимог, рішеннями, сценаріями приймання і задачами; знайти сироти, биті й неоднозначні ID.
**Хто.** Один агент або скрипт; оркестратор перевіряє вибірку рядків.
**Вхід.** Схема ID з промпту 01 (`{{ID_SCHEME}}`), документи всіх рівнів, беклог.
**Вихід.** `{{AUDIT}}/TRACE-MATRIX.md`, `F-{{PREFIX}}-NNN.md`, журнал `L-{{PREFIX}}.md`.

## Промпт

```text
{{COMMON_RULES}}

Задача: лінза T (трасування). Схема: {{ID_SCHEME}}. Префікс знахідок: {{PREFIX}}.
Журнал: {{AUDIT}}/lenses/L-{{PREFIX}}.md (створи першим). Матриці: {{AUDIT}}/TRACE-MATRIX.md.
Знахідки: {{AUDIT}}/findings/F-{{PREFIX}}-NNN.md. Документи не змінюй.

1. Визначення ID. Пошуком заголовків (а не назв файлів) знайди, де визначено кожен ID кожного рівня.
   Результат: таблиця «ID, файл:рядок заголовка». Познач дублікати визначень і пропуски в нумерації.
   Окремо перевір, чи номер документа не збігається з номером вимоги (наприклад, файл «SWR-06-…» і вимога SWR-06
   в іншому файлі). Це дефект позначень, а не обов'язково колізія вимог.
2. Посилання. Знайди всі згадки ID у {{DOCS}} і {{BACKLOG}}. Для кожного посилання на неіснуючий ID — рядок
   у таблиці «биті посилання» з `шлях:рядок`. Перевір і посилання на пункти («SWR-43 п. 4»): чи існує такий пункт.
3. Матриця вниз. Для кожної вимоги верхнього рівня — дочірні вимоги за полем батьківського посилання.
   Сироти: вимоги без дочірніх і дочірні без батька.
4. Матриця вбік. Для кожної вимоги ПЗ — посилання на рішення, специфікації, сценарії використання,
   сценарії приймання (прямі згадки ID в обидва боки). Вимоги без жодного посилання — окремим списком.
5. Беклог. Для кожної вимоги — задачі, що на неї посилаються; задачі в done без посилання на вимогу;
   задачі в todo/blocked, що посилаються на неіснуючі або змінені ID.
6. Реєстри. Звір індекси (README з переліком ADR, UAT, SPEC тощо) з фактичними файлами: кількість, назви, статуси.
7. Знахідки: дефекти ID, сироти з істотними наслідками, розбіжності реєстрів. Матриці — у TRACE-MATRIX.md.

Не роби висновку про покриття кодом: це промпт 17.
```

## Перевірка результату

- Кількість ID у матриці дорівнює кількості визначень.
- Вибірка 10 «битих» посилань перевірена вручну.

## Типові помилки

- Пошук ID за назвами файлів.
- Посилання на ID в тексті вважається трасуванням, навіть якщо це згадка «на відміну від SWR-X».
