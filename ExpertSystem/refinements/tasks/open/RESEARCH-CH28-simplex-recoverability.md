# RESEARCH-CH28-simplex-recoverability. Досяжність безпечного стану Simplex

**ID:** RESEARCH-CH28-simplex-recoverability  
**Статус:** Відкрито; модель руху та часові свідчення не надані.  
**Власник:** дослідник теорії керування та розробник VIDA апаратного арбітра.  
**Пріоритет:** P0 — фізична безпека розширеного профілю.  
**Підстава:** [аудит W27-30-10](../../audit-2026-10-28-ch27-ch30.md), [CH28 §9.1–§9.2.1, 660–748](../../../ch28-dual-mode-expert-systems.md).  
**Вимоги:** [L1](../../../requirements/L1-stakeholder/ch28-L1-stakeholder.md): REQ-L1-28-10, REQ-L1-28-11; [L2](../../../requirements/L2-system/ch28-L2-system.md): REQ-L2-28-16, REQ-L2-28-17; [L3](../../../requirements/L3-component/ch28-L3-component.md): REQ-L3-28-16, REQ-L3-28-17, REQ-L3-28-18, REQ-L3-28-19.

## 1. Залежності та межі

Доведення має встановити, коли baseline-контролер справді повертає об'єкт у safe set, а не тільки коли арифметично додатний margin. А-22 зберігається: це розширений апаратно-програмний профіль, не вимога до кожного мережевого сервісу.

Потрібні погоджені plant/ODD, допустимі невизначеності, модель приводу, sensor bounds та safe set. [CH18 WCET/DMA](RESEARCH-CH18-wcet-dma-proof.md) є джерелом апаратних часових передумов; ця задача не повторює його тестбенчі.

## 2. Безпечний спростовуваний протокол

1. Почати з чисельної моделі візка без фізичного приводу. Задати швидкість, зчеплення, затримку сенсора, насичення, межі стану й керування. Одержати recoverable set незалежним reachability-аналізом або barrier/Lyapunov-доказом.
2. Порівняти часовий margin з oracle досяжності: номінал; мінімальне зчеплення; пропущений/старий heartbeat; граничний стан; втрачений сенсор; затриманий trip; недостатня гальмівна дія.
3. Базові варіанти: завжди baseline, незахищений advanced лише в симуляції, кандидатний Simplex. Перевірити старт, REFUSAL-тригер, latch, stationary guard, operator reset та відсутність автоматичного повернення в русі.
4. Скласти неперекривний worst-case budget sense→arbiter→switch→recovery. Після доказу можна застосувати logic-only HIL з індикатором замість приводу; не вимикати watchdog, не випробовувати рух біля людей.

## 3. Targets, PASS/FAIL і негативний результат

Книжкові 170 мс recovery, 14 мкс прикладу, <50 мкс switch, 60 мс threshold і dwell≥5×FTTI — **заяви/кандидатні цілі, застосовність яких очікує погодження**, не встановлені тут виміри. Не послаблювати їх за результатом невдалого тесту без нового baseline-рішення.

**PASS:** формальна область гарантії з явними припущеннями, часовий доказ і результати контролів. **FAIL:** стан поза recoverable set при дозволеному AI, неврахована затримка або небезпечний reset. Публікувати контрприклад/межу застосовності; максимум спостережень не називати WCET.

## 4. Артефакти, команди й оновлення

Передати модель, одиниці, початкові стани/seed, solver/version, proof certificates, simulation traces, constraints/STA або логічні захоплення trip, хеш RTL/firmware. Надати точні команди обраного симулятора й test runner після вибору інструмента; довільного існуючого API не припускати.

Безпечна початкова команда перевіряє лише книжкову арифметику, не recovery-доказ:

```bash
python3 -c 'hazard_ms=1000*0.44/2.0; margin_ms=hazard_ms-170; assert margin_ms==50; print("margin_ms",margin_ms,"trip",margin_ms<60)'
```

Оновити CH28 §9.1 (гарантія baseline), §9.2 (область margin), §9.2.1 (повний budget/числовий приклад/reset). Узгодити всі перелічені вимоги, зокрема REFUSAL-тригер і доказовий статус чисел. Не змінювати мережеві профілі А-11.
