# RESEARCH-CH18. Збереження семантики при алгебраїчному прискоренні

**Статус:** Відкрито; трансляції й заяви еквівалентності не доведено.
**Виконавець:** дослідник логіки/GraphBLAS, розробник прискорювача та інженер формальної верифікації.
**Пріоритет:** високий для допускового піднабору.
**Джерела:** [аудит W16-20-19, -31](../../audit-2026-10-28-ch16-ch20.md), [глава 18, §9.2, рядки 1200–1267](../../../ch18-execution-infrastructure.md).
**Пов'язані вимоги:** REQ-L1-18-12, REQ-L2-17-02 — суміжні; прямих L3-контрактів трансляцій GraphBLAS/Ising/автоматів немає.
**Залежності:** семантика → доведення відповідності → вимірювання. Для Q16.16 використати [контракт провайдерів](RESEARCH-CH18-execution-provider-contract.md); суто булеві тести незалежні.

## 1. Проблема та свідчення

Булева матриця суміжності поширює досяжність, але не кодує кон'юнктивні передумови сама по собі. Для `a AND b → c` при векторі `(1,0)` просте OR-агрегування двох ребер дає хибну активацію. Симетричний позитивний зв'язок Ізінга однаково оцінює два протилежні стани, хоча імплікація карає лише один.

Крім того, довільний автомат Глушкова не визначено лише парою SHIFT/AND; фіксовану TCAM-місткість не можна замінити безмежним O(1). Benchmark до збереження семантики порівнює різні задачі.

## 2. Спростовуваний протокол і еталони

1. Для кожної заявленої трансляції задати вхідну мову, модель істинності, допустимі правила, кодування, оператор обчислення й декодування результату.
2. Для GraphBLAS почати з унарної досяжності, потім кон'юнкцій, альтернативних обґрунтувань, циклів, явного заперечення, суперечності та невідомого. Окремо визначити дефітери/пріоритети ASPIC+, якщо їх заявлено.
3. Порівняти всі оцінки малих скінченних моделей із простим точним логічним еталоном. Контроль — мінімальний контрприклад з аудиту; він має перестати породжувати зайвий факт.
4. Для Ізінга визначити таблицю істинності кожної норми, лінійні поля, допоміжні змінні й штрафи. Перебрати всі малі стани та довести відповідність мінімумів допустимим конфігураціям.
5. Евристичний мінімізатор перевіряти підстановкою результату й, де потрібно, незалежним сертифікатом оптимальності. Не ототожнювати знайдений допустимий стан із глобальним оптимумом.
6. Для автоматів порівняти бітову реалізацію з прямим NFA/DFA на класах із повторенням, альтернативами й необов'язковими фрагментами; опублікувати підтримуваний підклас для однієї SHIFT/AND.
7. Лише після проходження семантичних тестів виміряти однакові операції CPU/прискорювача, включно з підготовкою даних і формуванням доказових залежностей.

## 3. Цілі, PASS/FAIL і негативний результат

Ціль семантичного етапу — еквівалентність на визначеному піднаборі й доказ її загального твердження або явна межа лише тестової перевірки. Нових цілей швидкодії немає; 42/38 мкс, 347-кратне прискорення та глобальний оптимум за мілісекунди **очікують окремого протоколу**, не приймаються за готові пороги.

**PASS піднабору:** оприлюднено трансляцію, передумови й перевірний аргумент збереження семантики. **FAIL:** мінімальний контрприклад публікується; піднабір звужується або трансляція виправляється. Непідтримувану ASPIC+-операцію не приховувати в агрегованій точності.

## 4. Відтворення й оновлення

Передати формальні означення, еталон, генератор малих моделей, усі контрприклади, доказ/сертифікати, версії бібліотек і лише потім benchmark.

Оновити главу 18 §9.2.1–§9.2.5: точні класи задач, обмеження апаратури й статус чисел. Витягнути прямі L2/L3 тільки для погодженого профілю; концептуальний каталог не робити обов'язковим для мінімальної ЕС.
