# RESEARCH-CH29-update-noninterference. Невтручальність оновлень бази знань

**ID:** RESEARCH-CH29-update-noninterference  
**Статус:** Відкрито; абсолютну незалежність за назвою домену не доведено.  
**Власник:** дослідник немонотонної логіки та розробник VIDA версійованої бази знань.  
**Пріоритет:** P0 — незмінність незачеплених висновків.  
**Підстава:** [аудит W27-30-15](../../audit-2026-10-28-ch27-ch30.md), [CH29 §7.1, 652–671](../../../ch29-neuro-symbolic-architecture.md).  
**Вимоги:** [L1](../../../requirements/L1-stakeholder/ch29-L1-stakeholder.md): REQ-L1-29-05, REQ-L1-29-13; [L2](../../../requirements/L2-system/ch29-L2-system.md): REQ-L2-29-09, REQ-L2-29-14; [L3](../../../requirements/L3-component/ch29-L3-component.md): REQ-L3-29-11, REQ-L3-29-12.

## 1. Мета та справжні залежності

Мета — визначити «ортогональний запит» відсутністю впливу у повному графі залежностей, а не назвою дисципліни. RCU дає атомарну публікацію snapshot, але не гарантує семантики іншого snapshot. Нульовий градієнт окремо спростовує універсальну необхідність дрейфу мовної моделі.

Формальний доказ залежить від [CH20 frozen trace](RESEARCH-CH20-frozen-trace-monotonicity.md): треба знати, що заморожено й яку множину змінюють. Small-model generator можна готувати раніше. [П-06 беклогу](../../book-refinement-backlog.md#п-06-атомарна-ревізія-не-є-нульовою-затримкою-або-стиранням-історії) про 0 мс не перевідкривати.

## 2. Спростовуваний безпечний протокол

1. Визначити мову правил, positive/negative/defeater dependencies, versioned scope, query semantics та revocation.
2. Побудувати синтетичні домени з окремими й спільними предикатами. Контролі: суто локальна поправка; спільний predicate; від'ємна передумова; зміна рангу; новий defeater; каскад відкликання; альтернативний proof.
3. Порівняти incremental evaluation з повним recompute на тому самому snapshot. Для запитів поза доведеною dependency closure результати мають бути еквівалентні; domain label не oracle.
4. Визначити snapshot-lifetime і RCU-reader pinning. Старий reader завершує стару ревізію; новий не отримує суміш двох KB. Зберігати історичні сертифікати без переписування їх під новий snapshot.
5. Розділити proof невтручальності, тести публікації й cascade invalidation. Не виконувати експериментів з приватними моделями/даними або real-time приводами.

## 3. Цілі та рішення

Ціль — машиноперевірний або рецензований доказ обмеженої теореми. Нових targets затримки немає; 0 мс простою не доказ локальності й не предмет нового benchmark.

**PASS:** явні передумови й залежності, доказ та збіг з recompute у контрольних моделях. **FAIL початкової універсальності:** мінімальний контрприклад і виправлена область; негативний результат публікується. Нуль counterexamples у скінченному переборі не замінює теореми.

## 4. Артефакти й точні оновлення

Передати формальну специфікацію, dependency graphs, exhaustive generator, proof/сертифікат, версії solver/рушія, snapshots і raw query diff. Надати команди обраного proof checker та runner після їх визначення, не припускати існування неперевірених CLI.

Початковий контроль показує, чому одна назва домену не є ізоляцією залежностей:

```bash
python3 -c 'defect_before=False; defect_after=True; query=lambda defect:not defect; assert query(defect_before)!=query(defect_after); print("shared negative dependency changes the query")'
```

Оновити CH29 §7.1: обидві формули, означення ортогональності, таблицю локальності й NOTE про абсолютну незмінність. Синхронізувати перелічені вимоги, зберігши потребу оновлювати норми без retraining і А-14 `REVOKED`→`INVALIDATED_BY_REVOCATION`.
