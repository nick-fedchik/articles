# RESEARCH-CH02-RELATIONAL-RANK. Доказова інтерпретація реляційного рангу

**ID:** RESEARCH-CH02-RELATIONAL-RANK  
**Статус:** Відкрито; семантику рангу не верифіковано, production-реалізацію не досліджено.  
**Власник / роль:** дослідник немонотонної логіки та інженер вимог; розробник VIDA символьного рушія залучається лише після визначення контракту.  
**Пріоритет:** P1 — висока тяжкість неоднозначного доказового допуску.  
**Нова підстава:** [W01-03-02](../../audit-2026-10-28-ch01-ch03.md#w01-03-02-входження-факту-в-передумови-правила-не-є-доказом-цього-факту).  
**Джерело:** [CH02 §5.1](../../../ch02-epistemology-of-machine-knowledge.md), поточні рядки 245–280; контроль семи дисциплін 114–123 і фінального шлюзу 1099–1132.  
**Вимоги:** [L2 CH02](../../../requirements/L2-system/ch02-L2-system.md): `REQ-L2-02-01`, `REQ-L2-02-15`; [L3 CH02](../../../requirements/L3-component/ch02-L3-component.md): `REQ-L3-02-01`, `REQ-L3-02-07`, `REQ-L3-02-25`, `REQ-L3-02-26`.  
**Відома знахідка — existing finding:** [П-01](../../book-refinement-backlog.md#п-01-проміжний-реляційний-ранг-і-пріоритет-захисної-заборони). Для неї бракує однозначного приймального oracle; цей контроль не є новою знахідкою.

## 1. Мета й межа дослідження

Ранг, побудований на кількості правил, які **використовують** факт, може оцінювати його структурну важливість, але не надає доказу самого факту. Потрібно перевірити, чи можна зберегти авторську модель як допоміжний індекс без змішування з аргументаційною підтримкою й нормативним допуском.

Спростовувана гіпотеза: додавання правила «якщо f, то новий висновок» без нових доказів f **не повинно підвищувати доказовий статус f**. Числовий індекс використаності при цьому може змінитися. Завдання не стверджує, що реальний рушій допускає такий bypass.

## 2. Залежності та погоджені цілі

1. Автор/власник baseline визначає семантику f, Prem, підтримки й активного defeater та статус рангу: індекс маршрутизації чи критерій доказового допуску.
2. Зберігаються А-04, А-07/А-08, А-12/А-13: детермінований доказ для критичного ACCEPT, затвердження baseline людиною, канонічні verdict і явний нормативний пріоритет. Кількість слабких аргументів не може мовчки скасувати чинну заборону.
3. До емпіричного висновку потрібні затверджена таблиця «заборона / чинність waiver / статус підтримки / ранг / verdict / право виконання» та scope застосування профілю. **Пріоритет для проміжного рангу П-01 ще очікує погодження.**
4. Ваги 1–10 і поріг 1 взято з CH02 як предмет перевірки, **не як схвалені цим завданням нормативи**. Нових статистичних, часових чи безпекових порогів не вводити.
5. Загальний доказ композиції належить наявному [RESEARCH-CH28-composition-proof](RESEARCH-CH28-composition-proof.md); його експеримент не повторювати. Дослідження рангу може початися незалежно на скінченній моделі.

## 3. Безпечний синтетичний протокол, baselines і controls

Протокол виконується лише в програмній моделі над штучними фактами й правилами; обладнання, справжні нормативні допуски та конфіденційні корпуси не використовуються.

1. Опублікувати схему скінченного графа: атоми, спостережені/затверджені факти, умовні правила, head/premises, застосовність, нормативний пріоритет, атаки та походження. Відокремити «є запис» від «є чинний доказ».
2. Реалізувати три незалежні baselines: точний обхід усіх доказів у визначеному скінченному фрагменті; надрукований incidence-rank; кандидатний ранговий індекс із незалежним фінальним шлюзом. Oracle не повинен викликати ту саму функцію ранжування.
3. Відтворити W01-03-02: жодного доказу f, лише f→a та f→b з вагами 8/6. За формулою rank=14. Зіставити числовий результат і окремо результат доказового oracle.
4. Метаморфні controls: додати споживача f; продублювати правило/джерело; переставити правила; перейменувати ID; прибрати єдину підставу f; додати справжній незалежний доказ. Для перших перетворень доказовий статус не змінюється, для останніх його зміна має пояснюватися oracle.
5. Позитивні controls: підтверджений ізольований факт; підтверджений факт, використаний багатьма правилами; коректно виведений факт. Негативні: самопідтримуваний цикл без зовнішньої підстави, нечинне правило, підміна цитати, активна нормативна заборона.
6. **Окреме відтворення existing finding П-01:** 14/(1+7)=1,75 і 6/(1+7)=0,75; варіювати чинність waiver та наявність заборони незалежно від числа. Не встановлювати очікуваний verdict для 0,75 до погодження таблиці. Без права виконання можуть співіснувати діагностична ескалація й канонічна відмова.
7. Вичерпно перелічити малий, опублікований скінченний простір моделей; явно зафіксувати його межі та ліміти генератора. Зберегти всі розбіжності, а не лише приклади, на яких метод пройшов.
8. Для кандидатного контракту надати доказ, що структурний індекс не перетворює непідтверджений атом на аксіому. Якщо перевіряється лише допоміжна евристика, так і назвати результат.

## 4. Артефакти й команди

Передати специфікацію моделі, таблицю oracle, синтетичний корпус/генератор із seed або вичерпним порядком, окремі реалізації baselines, журнал усіх випадків, мінімальні контрприклади, результати PASS/FAIL і машинні SHA-256. Апаратні 3,2 МБ/180 нс не верифікуються цим семантичним експериментом.

Нижче — **запропоновані команди майбутнього стенда**; каталог і тести потрібно створити в окремому дозволеному дослідницькому робочому просторі. Зараз ці команди не виконано й файлів стенда не створено:

```bash
python3 -m unittest discover -s experiments/ch02_rank -p 'test_*.py'
python3 scripts/inspect_requirements_trace.py --check-sections
```

Для кожного запуску зберегти revision, параметри генератора, повний stdout/stderr і exit code. Невідомий verdict не записувати як PASS.

## 5. PASS/FAIL і публікація негативного результату

- **PASS кандидатного контракту:** є погоджена таблиця й незалежний oracle; непідтверджений f не отримує доказового статусу від додавання споживачів; перестановка/дублювання не змінює нормативного verdict; усі очікування скінченного корпусу виконано й математичний scope висновку названо.
- **FAIL вихідної доказової інтерпретації:** достатній один опублікований випадок, де rank названо підтримкою без доказу f. Це може спростувати інтерпретацію, не саму корисність індексу маршрутизації.
- **Не завершено:** непогоджена проміжна політика або відсутній незалежний oracle. Заборонено приховати це зменшенням порога чи переіменуванням FAIL.
- Негативний результат, усі controls і межі застосовності публікуються разом із позитивними. Результати не дають сертифікації ASIL.
