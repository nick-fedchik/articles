# Memo-013. Аргументи гарантування, атестації свідчень і видобування аргументів

**Тип:** технічний меморандум (інженерний memorandum).

**Дата:** 2026-10-03.

**Статус:** протокол запропонованих дослідів; SACM-інструменти, in-toto, Rekor і ASPARTIX у цьому проході не запускалися.

**Пов'язана глава:** [27](../ch27-safety-case-gsn-synthesis.md).

## Питання й гіпотези

Чи може експертна система зібрати аргумент гарантування так, щоб кожне свідчення мало перевірене походження, кожна зміна була видима в журналі, а сумнів рецензента мав формальний статус, а не губився в коментарях?

H-MUT: перевірки P0–P3 з глави 27 виявляють кожну навмисно внесену структурну ваду аргументу рівно тим правилом, для якого вада призначена. H-ATT: атестація звіту випробування з підписом і переліком суб'єктів виявляє будь-яку зміну байтів звіту або метаданих. H-LOG: журнал прозорості для послідовних коренів аргументу дає доказ включення й доказ узгодженості, розмір яких росте логарифмічно від кількості вузлів. H-ARG: вбудоване обчислення обґрунтованого розширення збігається з результатом ASPARTIX на випадкових графах атак. H-MINE: видобування кандидатних зв'язків простежуваності скорочує ручний пошук, але не змінює статусу зв'язку без рецензента. Спростування дає хоча б одна змінена атестація, яка проходить перевірку, або розбіжність з ASPARTIX без пояснення.

## Базова модель і варіанти

Базою є програма глави 27: дев'ять вузлів аргументу, перевірки P0–P3, дерево Меркла з сіллю HMAC для листів і обчислення обґрунтованого розширення. Варіанти додають формати й інструменти по одному.

| Варіант | Що змінюється | Що перевірити |
|---|---|---|
| A0 | програма глави без змін | відтворення восьми рядків виводу й кореня `8d2bbbc813e23883` |
| A1 | експорт аргументу в метамодель SACM 2.3 [[1]](#src-1) | які вузли, зв'язки й атрибути зберігаються після експорту й зворотного імпорту |
| A2 | атестації in-toto для звітів випробувань [[2]](#src-2) | виявлення зміни звіту, суб'єкта й типу предиката |
| A3 | атестації походження SLSA для збірки пакета знань [[3]](#src-3) | відповідність збирача, вхідних матеріалів і результату |
| A4 | приватний журнал прозорості Rekor [[4]](#src-4) | доказ включення й доказ узгодженості для кожного нового кореня |
| A5 | ASPARTIX як незалежний розв'язувач аргументаційних систем [[5]](#src-5) | збіг обґрунтованого розширення й різниця з іншими семантиками |
| A6 | реєстр спростувачів за підходами Assurance 2.0 [[6]](#src-6) і елімінативної аргументації [[7]](#src-7) | статус кожного спростувача й заборона закрити ціль із відкритим спростувачем |

## Власник і межі

Власник аргументу гарантування визначає структуру цілей і допустимі стратегії. Власник випробувального стенда підписує звіти. Рецензент безпеки вирішує, чи достатнє свідчення і чи закрито спростувач. Експертна система перевіряє структуру, походження й узгодженість, але не оцінює достатності аргументу. Для дослідів використовують синтетичні або знеособлені звіти; ключі підпису дослідного стенда не застосовують до робочих артефактів.

| ASR-06 | публікувати корені аргументу в приватний журнал прозорості | доказ включення для кожного кореня, доказ узгодженості між послідовними коренями, розмір доказу проти кількості вузлів |
| ASR-07 | порівняти вбудоване обґрунтоване розширення з ASPARTIX на випадкових графах від 5 до 200 аргументів | нуль розбіжностей; для порожнього обґрунтованого розширення записати переважні й стабільні розширення як контраст |
| ASR-08 | завести реєстр спростувачів для кожної цілі | жодна ціль не має статусу «закрита» з відкритим спростувачем; частка цілей, для яких розглянуто хоча б один спростувач |

| ASR-10 | розмітити коментарі рецензентів за типами спростувачів двома експертами | коефіцієнт узгодженості Коена між експертами до будь-якого навчання класифікатора |
| ASR-11 | спробувати відновити вміст прихованого листа перебором за опублікованими сусідніми хешами | без солі вердикт PASS або FAIL відновлюється одразу; із сіллю HMAC без ключа перебір не дає результату |
| ASR-12 | побудувати аргумент для двох ревізій обладнання в окремих гілках | перевірка P3 не дає хибної тривоги, якщо кожна гілка має власний контекст ревізії |

## Метрики й зупинка

Для мутацій звітувати частку виявлених мутацій за типом і кількість хибних тривог на незміненому аргументі. Для атестацій звітувати частку змінених артефактів, які пройшли перевірку; очікуване значення дорівнює нулю. Для журналу прозорості звітувати розмір доказів включення й узгодженості та час перевірки. Для ASPARTIX звітувати кількість розбіжностей і час розв'язання за розміром графа.

Для видобування зв'язків звітувати точність і повноту серед перших 5, 10 і 20 кандидатів, а також час рецензента на один прийнятий зв'язок порівняно з ручним пошуком. Для коментарів рецензентів звітувати коефіцієнт Коена; якщо він нижчий за поріг, який погодив власник, класифікатор не навчають, а уточнюють інструкцію розмітки.

Дослід зупиняють, якщо змінений артефакт проходить перевірку, якщо розбіжність з ASPARTIX не має пояснення або якщо кандидатний зв'язок потрапляє до аргументу без рецензента.

## Аналіз даних

Історія мутацій, які пропустила перевірка, показує, яких структурних правил бракує. Частотний аналіз спростувачів за типами цілей підказує, які питання рецензенти ставлять найчастіше, і може стати шаблоном для нових аргументів. Кластеризація відхилених кандидатних зв'язків показує, де лексична подібність вимоги й тесту оманлива. Усі три результати є кандидатами для власника аргументу, а не новими правилами експертної системи.

## Очікуваний результат

Отримати набір мутацій аргументу з очікуваними правилами, звіт про втрати під час експорту в SACM, приклади атестацій і доказів журналу, порівняльну таблицю з ASPARTIX, реєстр спростувачів і розмічену вибірку зв'язків. Окремо записати межі: синтетичні звіти, одна ревізія обладнання в базовому прикладі, неперевірена масштабованість журналу й залежність метрик видобування від якості розмітки.

## Словник

| Термін | Значення |
|---|---|
| Атестація | підписане твердження про артефакт, яке пов'язує хеш артефакту з предикатом, наприклад результатом випробування |
| Журнал прозорості | журнал записів лише з додаванням, для якого можна отримати доказ включення й доказ узгодженості |
| Доказ включення | набір хешів, який показує, що запис входить до дерева з відомим коренем |
| Доказ узгодженості | набір хешів, який показує, що новіше дерево журналу продовжує старіше без зміни попередніх записів |
| Спростувач | обставина, яка може зробити твердження аргументу хибним або послабити підставу для нього |
| Мутація аргументу | навмисно внесена вада структури аргументу для перевірки того, чи виявить її правило |

| OMG | Object Management Group, консорціум стандартів моделювання |
