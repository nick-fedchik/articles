# Memo-007. Пошук доказів, семантична перевірка й вірність пояснення

**Тип:** технічний меморандум (інженерний memorandum).  
**Дата:** 2026-10-03.  
**Статус:** запропонований корпусний експеримент; генератори й оцінювачі не порівняно.  
**Пов'язані глави:** [19](../ch19-from-question-to-evidence.md), [20](../ch20-explanation-engine.md).

## Питання й гіпотези

Чи знаходить конвеєр усі потрібні підстави й передає їхній зміст людині без нових причин, втрати умов або витоку?

H-EVID: структурований пошук і перевірка ролей зменшать необґрунтовані відповіді проти базового пошуку з генерацією. H-EXPL: шаблон або вибір готових тверджень матиме менше семантичних помилок, ніж вільна генерація, при достатній зрозумілості. Гіпотези не підтверджуються лише високою оцінкою іншої мовної моделі.

## Три різні еталони

Еталон пошуку позначає релевантні фрагменти, еталон твердження задає повний семантичний запис, еталон пояснення задає достатні підстави й дозволені висловлювання. Не можна оцінити всі три задачі одним косинусом або фактом наявності цитати.

Потрібні відповіді, для яких число й одиниця лежать у різних реченнях, кілька чисел мають різні ролі, виняток стоїть у примітці, редакція змінює застосовність, а одна й та сама цитата повторюється. Додати запитання без доказу в корпусі, із доказом поза першими результатами та з конфліктними джерелами. Ці три випадки мають різні еталонні статуси.

Групи редакцій і перефразувань розподіляють за правилами [Memo-003](Memo-003-Semantic-Extraction-Weak-Supervision-And-Active-Learning.md). Експерти готують еталон незалежно від оцінюваного генератора. Відсутність джерела в перших результатах не є доказом відсутності норми.

## Матриця маршрутів

| Етап | Базовий варіант | Кандидат |
|---|---|---|
| Пошук | лексичний пошук із дозволеними ідентифікаторами | гібридний пошук, переранжування, структуровані запити |
| Прив'язка | точний фрагмент у відомій області | карта нормалізації та кілька пов'язаних джерельних діапазонів |
| Перевірка змісту | схвалені правила для вузького піднабору | модель текстового слідування як сигнал плюс рецензія |
| Пояснення X0 | детермінований шаблон | контрольний маршрут без генеративної моделі |
| Пояснення X1 | вибір готових тверджень | модель повертає лише дозволені ідентифікатори й порядок |
| Пояснення X2 | вільний текст | покомпонентна перевірка та повернення до шаблону |

Порівнювати зміни послідовно, а не міняти весь конвеєр одразу. X0–X2 отримують той самий перевірений граф і профіль доступу. Обмеження граматики контролює форму X1, рендерер контролює підстановку значень, а достатність вибраних підстав перевіряється окремо.

Методика CheckList допомагає підготувати перефразування й контрастні зміни [[1]](#src-1). Автоматизовані метрики RAGAS (*Retrieval Augmented Generation Assessment*) можуть прискорити аналіз [[2]](#src-2), але їхні оцінювачі не є незалежними формальними валідаторами. Тести зрозумілості потрібні окремо: пояснення є контрастним і залежить від запитання користувача [[3]](#src-3).

## Завдання для експертної системи

| ID | Дія | Очікуваний вихід |
|---|---|---|
| EVID-01 | схвалити три еталони й профілі доступу | фрагменти, семантичні записи, достатні підграфи |
| EVID-02 | порівняти маршрути пошуку | повнота всього набору підстав, не лише першої цитати |
| EVID-03 | перевірити порожні поля, якорі й повторені цитати | явне відхилення неповного запису |
| EVID-04 | змінити роль числа, одиницю, заперечення й редакцію | зміна змісту виявляється навіть за правильних цитат |
| EVID-05 | порівняти автоматичний сигнал із рецензією | помилки й відмови за незалежним еталоном |
| EXPL-01 | виконати X0–X2 на однакових графах | текст, вибрані підстави й статус перевірки |
| EXPL-02 | змінити текст, зберігши всі назви сутностей | шлюз ловить неправильне заперечення, ролі й причинність |
| EXPL-03 | перевірити HOW, WHY NOT і WHAT IF | повна траса, статус передумов і незмінний вихідний знімок |
| EXPL-04 | мінімізувати сумісні й несумісні набори | передумови QuickXPlain й мінімальність за включенням |
| EXPL-05 | перевірити контрфакт і запропоновану дію | бажаний результат у моделі, повноваження й умовність результату |
| EXPL-06 | змінити лише закриті дані у парних входах | дозволене подання не розкриває забороненої різниці |
| EXPL-07 | провести незалежний перегляд зрозумілості | час знаходження причини, правильне розуміння меж і наступного кроку |

## Негативні випадки

До набору включити «тест прострочений, тому реліз дозволено», дві цитати з правильними словами, але різними ролями, зміну MUST на SHOULD, число без одиниці, якір порожнього рядка, помилкове поле й втрачений виняток. У шаблонному маршруті перевірити також помилку самого шаблону: відсутність генератора не робить рендерер правильним.

Для WHY NOT відсутній факт не прирівнювати до суперечності. Для QuickXPlain потрібні сумісний фон, точний статус оракула й установлене несумісне об'єднання; мінімальний конфлікт не обов'язково найменший. Для WHAT IF дочірній знімок не змінює базу. План «запросити повторний тест» не гарантує його успіху.

Пояснення після маскування не позначати повним. Не розкривати кількість, назви або саму наявність закритих причин без окремого дозволу. Парні тести перевіряють також доступний вердикт, час, довжину тексту, кеш і журнал; видалення цитати саме по собі не забезпечує відсутності витоку.

## Метрики й приймання

| Показник | Що оцінює |
|---|---|
| Повнота набору підстав | чи знайдено всі необхідні фрагменти, включно з умовами й винятками |
| Точність семантичного запису | ролі, числа, одиниці, модальність, область і редакція |
| Частота помилок серед прийнятих | необґрунтовані відповіді при заданому охопленні |
| Вірність пояснення | частка суттєвих тверджень, підтверджених графом і контекстом |
| Достатність пояснення | чи містить подання потрібні для конкретного питання підстави |
| Правильність відмови | відрізнення браку даних, конфлікту, доступу й незавершеної перевірки |
| Витік | порушення наперед визначеної політики дозволеного подання |
| Зрозумілість і вартість | правильне розуміння рецензентом, час й частка повернення до шаблону |

Порожній текст не має автоматично отримувати максимальну вірність; знаменник і випадок без тверджень визначають до тесту. Для статистики використовувати групи намірів і документів, а не незалежні перефразування. Відсутність значущої відмінності не є доказом рівності: допустиму регресію задають заздалегідь.

Критичний контрольний випадок із витоком або домисленим нормативним висновком блокує запропонований автоматичний маршрут до перегляду. Нуль таких випадків у наборі не означає нульового ризику в майбутньому потоці. Власник може прийняти X1 лише для пояснень визначеного класу й залишити X0 для критичних рішень.

## Очікуваний результат

Зберегти еталони, маніфести, точні кандидати пошуку, записи прив'язки, перевірені графи, тексти й відмови X0–X2, каталог помилок і рішення. Звіт окремо називає твердження, підтверджені виконаними перевірками, та гіпотези для наступного досліду. Публікація знань і виконання запропонованих дій не входять до цього експерименту.
