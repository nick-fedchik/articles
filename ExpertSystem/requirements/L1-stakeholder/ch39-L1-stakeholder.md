## REQ-L1-39-01

- **Вимога:** Замовник повинен отримати експертну систему, яка сама аналізує інженерні артефакти та ставить питання без очікування запитів користувача.
- **Джерело:** [ch39](../../ch39-active-compliance-auditor-and-popperian-testing.md), §2.1 «Концепція проактивного доказового супроводу життєвого циклу».
- **Батьківська вимога:** немає (верхній рівень).
- **Метод верифікації:** Демонстрація.
- **Пріоритет:** P1 (Основна).
- **Статус:** Проєкт.

## REQ-L1-39-02

- **Вимога:** Замовник повинен отримати згенеровані чернетки TARA, SAR та DFAR із повною трасованістю `100,0 %` (`TraceabilityCoverage = 1,00`) до формалізованих вимог і пунктів норм.
- **Джерело:** [ch39](../../ch39-active-compliance-auditor-and-popperian-testing.md), §4 «Автоматизація генерації артефактів TARA, SAR та DFAR через доменні правила».
- **Батьківська вимога:** немає (верхній рівень).
- **Метод верифікації:** Аналіз.
- **Пріоритет:** P1 (Основна).
- **Статус:** Проєкт.

## REQ-L1-39-03

- **Вимога:** Замовник повинен отримувати для кожної гіпотези один явний результат із межами перевірки та джерельними підставами виявлених порушень. Відсутні застосовні норми, невідомий стан обов'язку, пошкоджений доказ або незавершена перевірка повинні давати `REFUSAL` із причиною, а не підтвердження доказів. Умовне підтвердження можливе лише після повної перевірки визначеного непорожнього застосовного фрагмента без порушень; воно не є доведенням фізичної безпеки або допуском релізу.
- **Джерело:** [ch39](../../ch39-active-compliance-auditor-and-popperian-testing.md), §3.2 «Пошук потенційного фальсифікатора (Potential Falsifier)»; §8, межі навчального аудитора.
- **Батьківська вимога:** немає (верхній рівень).
- **Метод верифікації:** Тест.
- **Пріоритет:** P0 (Критична / Безпекова).
- **Статус:** Проєкт.

## REQ-L1-39-04

- **Вимога:** Замовник повинен отримати блокування випуску, якщо метрики безпеки (`SPFM ≥ 0,99`, `LFM ≥ 0,90` для ASIL-D), трасованість (`TraceabilityCoverage = 1,00`) або фальсифікація (`RejectionRate = 1,00`) не відповідають встановленим порогам.
- **Джерело:** [ch39](../../ch39-active-compliance-auditor-and-popperian-testing.md), §3.2 «Пошук потенційного фальсифікатора (Potential Falsifier)», блок «Керування потоком верифікації та вердикти системи», §4.2 «Автоматизація DFAR та FMEDA», §6.1 «Розрахунок повноти тестової програми».
- **Батьківська вимога:** немає (верхній рівень).
- **Пов'язана вимога:** REQ-L1-36-17 стосується погіршення критичних показників після зміни; ця вимога окремо стосується відповідності встановленим порогам перед випуском.
- **Метод верифікації:** Тест.
- **Пріоритет:** P0 (Критична / Безпекова).
- **Статус:** Проєкт.
- **Перевірка:** Якщо встановлений поріг трасованості не виконано, випуск блокується навіть без порівняння з попередньою версією; визначення порогів потребує погодження.
