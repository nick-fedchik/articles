## REQ-L1-11-05

- **Вимога:** Замовник повинен отримувати для кожного кандидата числові показники замість словесних міток впевненості: точкову частоту на вибірці обсягу `n`, байєсівський 95-відсотковий інтервал шириною `Δp`, коефіцієнт каппа Коена `κ` і пояснений результат оцінювання. За коректних входів будь-яка умова `n < 10`, `Δp > 0,30` або `κ < 0,40` повинна давати `REFUSAL` незалежно від проміжних показників; лише за відсутності цих блокерів зона `10 ≤ n < 30`, `0,15 < Δp ≤ 0,30` або `0,40 ≤ κ < 0,75` дає `QUALIFIED` з ескалацією. Сукупне виконання `n ≥ 30`, `Δp ≤ 0,15`, `κ ≥ 0,75` означає готовність до подальшої доказової верифікації та погодження baseline, а не автоматичний `ACCEPT` або право застосування правила.
- **Джерело:** [ch11](../../ch11-knowledge-elicitation-from-experts.md), §6 «Математичне розмежування суб'єктивної впевненості та статистичної частоти».
- **Батьківська вимога:** немає (верхній рівень).
- **Метод верифікації:** Аналіз.
- **Пріоритет:** P0 (Критична / Безпекова).
- **Статус:** Проєкт.

## REQ-L1-11-11

- **Вимога:** Замовник повинен отримувати активне опитування, яке припиняється, коли очікуваний інформаційний виграш менший за `0,05 біта` або подальші запитання не окупають експертний час, причому достатність безпеки має абсолютний пріоритет над економічною зупинкою: якщо опитування зупинено за вартісним критерієм до досягнення порогової точності безпеки, правило отримує лише статус `QUALIFIED` (`ACCEPT_CONDITIONAL`) з позначенням залишкової невизначеності як відомого невідомого (`UNK`), але ніколи не `ACCEPT`.
