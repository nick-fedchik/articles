## REQ-L2-30-01

- **Вимога:** Експертна система повинна формувати перелік кандидатних колізій між цілями HARA і TARA для рецензії фахівцем.
- **Джерело:** [ch30](../../ch30-safety-cybersecurity-co-engineering.md), §1.1 «Чотири архетипові міжкатегоріальні колізії».
- **Батьківська вимога:** REQ-L1-30-01.
- **Метод верифікації:** Аналіз.
- **Пріоритет:** P1 (Основна).
- **Статус:** Проєкт.

## REQ-L2-30-02

- **Вимога:** Експертна система повинна позначати захисну реакцію, яка може порушити доступність, для перевірки фахівцем до погодження.
- **Джерело:** [ch30](../../ch30-safety-cybersecurity-co-engineering.md), §1.1 «Чотири архетипові міжкатегоріальні колізії» (колізія 2).
- **Батьківська вимога:** REQ-L1-30-02.
- **Метод верифікації:** Аналіз.
- **Пріоритет:** P1 (Основна).
- **Статус:** Проєкт.

## REQ-L2-30-03

- **Вимога:** Експертна система повинна перевіряти для кожного шляху атаки, що сума ARTI і FRTI з додатним запасом строго вкладається у FTTI. Для шляху, де затверджений профіль вимагає автентифікації кадру, виміряний найгірший час перевірки включається до ATDI/ARTI; невизначений per-frame deadline не може дати позитивний результат.
- **Джерело:** [ch30](../../ch30-safety-cybersecurity-co-engineering.md), §2.2 «Часовий бюджет ко-інженерії: FTTI проти ARTI».
- **Батьківська вимога:** REQ-L1-30-03.
- **Метод верифікації:** Тест.
- **Пріоритет:** P0 (Критична / Безпекова).
- **Статус:** Проєкт.

## REQ-L2-30-04

- **Вимога:** Експертна система повинна після виявлення втечі агента з пісочниці передати тривогу на вхід апаратного інтерлоку, який знімає лінію `permit` (низький рівень або обрив означає безпечний стан), програмно відкликати сесійні сертифікати й блокувати канал зв'язку до фізичного аудиту; втрата сигналу життєздатності шляху тривоги довше за `T_hb` також знімає `permit`.
- **Джерело:** [ch30](../../ch30-safety-cybersecurity-co-engineering.md), §1.2.1 «Інженерне замикання циклу розрахунку апаратного інтерлоку (Actionable Closed Loop)».
- **Батьківська вимога:** REQ-L1-30-04.
- **Метод верифікації:** Тест.
- **Пріоритет:** P0 (Критична / Безпекова).
- **Статус:** Проєкт.

## REQ-L2-30-05

- **Вимога:** Експертна система повинна відхиляти зі статусом `REFUSAL_UNVERIFIED_ACTION` дію агента, безпечність якої SMT-верифікатор не довів у межах параметра `T_SMT` (ціль проєкту; у прикладі глави 50 мс), зокрема за `sat`, `unknown`, помилки або таймауту.
- **Джерело:** [ch30](../../ch30-safety-cybersecurity-co-engineering.md), §1.2 «Автономна втеча агентів із пісочниць (Sandbox Escape), бенчмарк ExploitGym та апаратні інтерлоки» (шар 2).
- **Батьківська вимога:** REQ-L1-30-04.
- **Метод верифікації:** Тест.
- **Пріоритет:** P0 (Критична / Безпекова).
- **Статус:** Проєкт.

## REQ-L2-30-06

- **Вимога:** Експертна система повинна обчислювати оцінку здійсненності атаки за п'ятьма факторами затвердженого версійованого профілю для кожного сенсорного інтерфейсу. Якщо профіль заявляє відповідність ISO/SAE 21434, він повинен містити точний пункт чинної редакції; без такого посилання значення не класифікуються як нормативні.
- **Джерело:** [ch30](../../ch30-safety-cybersecurity-co-engineering.md), §2.1.1 «Оцінка здійсненності атаки (Attack Feasibility Rating) за ISO/SAE 21434».
- **Батьківська вимога:** REQ-L1-30-05.
- **Метод верифікації:** Тест.
- **Пріоритет:** P1 (Основна).
- **Статус:** Проєкт.

## REQ-L2-30-07

- **Вимога:** Якщо за затвердженим профілем здійсненність атаки має категорію High або Medium, експертна система повинна блокувати позитивний screening-висновок і передавати випадок політиці виробу. Режим строгої автентифікації активується лише коли його вимагає схвалена політика та застосовні вимоги.
- **Джерело:** [ch30](../../ch30-safety-cybersecurity-co-engineering.md), §2.1.3 «Інженерне замикання циклу TARA-арбітражу (Actionable Closed Loop)».
- **Батьківська вимога:** REQ-L1-30-05.
- **Метод верифікації:** Тест.
- **Пріоритет:** P1 (Основна).
- **Статус:** Проєкт.

## REQ-L2-30-08

- **Вимога:** Експертна система не повинна вважати додатковий screening gate пройденим, якщо затверджений профіль дає `F_attack < 20` і немає перевіреного пом'якшення. Проходження цього gate саме по собі не повинно закривати ціль безпеки без решти обов'язкових свідчень GSN/HARA.
- **Джерело:** [ch30](../../ch30-safety-cybersecurity-co-engineering.md), §2.1.2 «Синтез Security-Informed Safety Cases у нотації GSN».
