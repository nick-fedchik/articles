## REQ-L2-24-01

- **Вимога:** Експертна система повинна формувати діагностичний пакет доказів з полями справи, версії моделі, зрізу спостережень, діагнозів, конфліктів, припущень і `not_ruled_out`.
- **Джерело:** [ch24](../../ch24-system-diagnosis.md), §10 «Формування доказового діагностичного пояснення для інженера».
- **Батьківська вимога:** REQ-L1-24-01.
- **Метод верифікації:** Тест.
- **Пріоритет:** P1 (Основна).
- **Статус:** Проєкт.

- **Вимога:** Експертна система повинна розрізняти первинну причину й вторинний аварійний наслідок, стійку несправність і перехідну заваду, а також ефект відновлювальної дії й спонтанне затухання.

## REQ-L2-24-07

- **Вимога:** Експертна система повинна обирати перевірку з максимальною додатною корисністю `U(T) > 0`, припиняти зондування при `U(T) ≤ 0` і переводити об'єкт у безпечну зупинку, якщо очікувані витрати досягають катастрофічного ліміту `J(π*) ≥ C_catastrophic`.
- **Джерело:** [ch24](../../ch24-system-diagnosis.md), §8 «Оптимізація наступної перевірки за цінністю інформації (VOI)»; §12 «Верифікація діагностичної експертної системи та оцінка ефективності».

- **Метод верифікації:** Тест.
- **Пріоритет:** P0 (Критична / Безпекова).
- **Статус:** Проєкт.

## REQ-L2-24-08

- **Вимога:** Експертна система повинна допускати автономний вердикт (`ACCEPT`) лише за селективного ризику `R_sel(c) ≤ 0,02` та покриття `Cov ≥ 0,85`, у проміжній зоні покриття `0,70 ≤ Cov < 0,85` присвоювати статус `QUALIFIED` з обов'язковою ескалацією людині-експерту, а при `Cov < 0,70`, `R_sel(c) > 0,02` або за однієї з семи обставин неповноти повертати типізовану відмову `REFUSAL`.
- **Джерело:** [ch24](../../ch24-system-diagnosis.md), §11 «Алгоритмічний скепсис: критерії відмови за неповноти спостережень».
- **Батьківська вимога:** REQ-L1-24-04.
- **Метод верифікації:** Тест.
- **Пріоритет:** P0 (Критична / Безпекова).
- **Статус:** Проєкт.
