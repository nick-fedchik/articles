## REQ-L2-35-01

- **Вимога:** Експертна система повинна приймати події через неблокуючу шину з типізованим записом: ідентифікатор, топік, джерело, часова мітка, пріоритет, навантаження та відбиток.
- **Джерело:** [ch35](../../ch35-self-organizing-expert-systems-synergetics-and-npu-runtime.md), §2 «Реактивне програмування та потоки подій як епістемічні імпульси».
- **Батьківська вимога:** REQ-L1-35-01.
- **Метод верифікації:** Тест.
- **Пріоритет:** P1 (Основна).
- **Статус:** Проєкт.

## REQ-L2-35-02

- **Вимога:** Експертна система повинна переглядати висновки після надходження події, а не лише у відповідь на запит оператора.
- **Джерело:** [ch35](../../ch35-self-organizing-expert-systems-synergetics-and-npu-runtime.md), §1, пункт 2 «Пасивна парадигма «запит / відповідь»».
- **Батьківська вимога:** REQ-L1-35-01.
- **Метод верифікації:** Тест.
- **Пріоритет:** P1 (Основна).
- **Статус:** Проєкт.

## REQ-L2-35-03

- **Вимога:** Експертна система повинна завершувати цикл реакції на подію, що змінює висновок, строго менше ніж за 5 мілісекунд (`< 5 мс`), а при перевищенні цього дедлайну негайно переходити в захисний режим `Fail-Closed`.
- **Джерело:** [ch35](../../ch35-self-organizing-expert-systems-synergetics-and-npu-runtime.md), §1, пункт 3 «Енергетична та часова непридатність пакетного перезавантаження».
- **Батьківська вимога:** REQ-L1-35-02.
- **Метод верифікації:** Тест.
- **Пріоритет:** P0 (Критична / Безпекова).
- **Статус:** Проєкт.

## REQ-L2-35-04

- **Вимога:** Експертна система повинна виконувати повне перезбирання пакета знань поза циклом реакції на події.
- **Джерело:** [ch35](../../ch35-self-organizing-expert-systems-synergetics-and-npu-runtime.md), §1, пункт 3 «Енергетична та часова непридатність пакетного перезавантаження».

- **Статус:** Проєкт.

## REQ-L2-35-05

- **Вимога:** Експертна система повинна створювати активний дефітер для факту з сенсорною аномалією і негайно відхиляти запити до цього факту.
- **Джерело:** [ch35](../../ch35-self-organizing-expert-systems-synergetics-and-npu-runtime.md), §4, інваріанти 1 і 3.

- **Статус:** Проєкт.

## REQ-L2-35-06

- **Вимога:** Експертна система повинна за єдиним каскадним протоколом відкликання позначати первинний інвалідований факт статусом `REVOKED`, а всі залежні похідні висновки в графі обґрунтування синхронно переводити у статус `INVALIDATED_BY_REVOCATION`.
- **Джерело:** [ch35](../../ch35-self-organizing-expert-systems-synergetics-and-npu-runtime.md), §4, інваріант 2 «Каскадний підрив підстав (Undercutting)».

## REQ-L2-35-07

- **Вимога:** Експертна система повинна зберігати для кожного висновку перелік засновків, цитат і шлях виведення, достатній для побайтового відтворення.
- **Джерело:** [ch35](../../ch35-self-organizing-expert-systems-synergetics-and-npu-runtime.md), §1, пункт 4 та §3 «Багаторівнева гібридна пам'ять L0 / L1: незмінний золотий базис та динамічний дельта-граф».

- **Метод верифікації:** Тест, Аналіз.
- **Пріоритет:** P0 (Критична / Безпекова).
- **Статус:** Проєкт.

## REQ-L2-35-08

- **Вимога:** Експертна система повинна видавати висновок як верифікований лише за виконання конструктивного шлюзового інваріанта `ZHR_gate = 1,00` (кожна випущена теза має побайтово підтверджену цитату з L0 або L1), тоді як на скінченних вибірках із `N` випробувань емпірична частота помилок подається односторонньою 95 % верхньою межею `p_U = 1 - 0,05^(1/N)`.
- **Джерело:** [ch35](../../ch35-self-organizing-expert-systems-synergetics-and-npu-runtime.md), §9.1 та висновок 2.
- **Батьківська вимога:** REQ-L1-35-04.
- **Метод верифікації:** Тест.
- **Пріоритет:** P0 (Критична / Безпекова).
- **Статус:** Проєкт.

- **Вимога:** Експертна система повинна зберігати базовий набір норм L0 незмінним і доступним лише для читання протягом експлуатації.
- **Джерело:** [ch35](../../ch35-self-organizing-expert-systems-synergetics-and-npu-runtime.md), §3, таблиця шарів пам'яті (шар L0).

## REQ-L2-35-10

- **Вимога:** Експертна система не повинна дозволяти реструктуризації шару L1 змінювати, підміняти або скасовувати норми шару L0.

## REQ-L2-35-11

- **Вимога:** Експертна система повинна підтримувати динамічний шар L1 в оперативній пам'яті як конфліктно-вільний реплікований дельта-граф (CRDT) із часом доступу менше `100 нс` і автоматично перебудовувати його конфігурацію, щойно змінюється макроскопічний параметр порядку середовища `ξ_order`.
- **Джерело:** [ch35](../../ch35-self-organizing-expert-systems-synergetics-and-npu-runtime.md), §3 «Багаторівнева гібридна пам'ять L0 / L1», §3.2.2 «Принцип підпорядкування Хакена» та §5.1 «Re-Search».
- **Батьківська вимога:** REQ-L1-35-06.
- **Метод верифікації:** Демонстрація.
- **Пріоритет:** P1 (Основна).
- **Статус:** Проєкт.

## REQ-L2-35-12

- **Вимога:** Експертна система повинна при зростанні індексу передбіфуркаційної нестабільності середовища `γ_crit = Var(Δξ_order) / σ0² ≥ 3,0` ставити безпекові інваріанти вище оптимізаційних критеріїв (`Survival Dominance`).
- **Джерело:** [ch35](../../ch35-self-organizing-expert-systems-synergetics-and-npu-runtime.md), §5.2.1 «Критерії диспетчеризації та фазові переходи станів».

- **Метод верифікації:** Тест.
- **Пріоритет:** P0 (Критична / Безпекова).
- **Статус:** Проєкт.

- **Джерело:** [ch35](../../ch35-self-organizing-expert-systems-synergetics-and-npu-runtime.md), §3, таблиця шарів пам'яті (карантинний буфер).

## REQ-L2-35-14

- **Вимога:** Експертна система повинна в межах розширеного апаратно-програмного профілю розподіляти обчислення між DSP (`50–200 мВт`), Edge NPU (`1–5 Вт`), FPGA EPU (програмованою логічною матрицею) і центральним процесором Host CPU (`3–10 Вт`, у межах бюджету бортового комплексу `15 Вт`), виконуючи остаточну криптографічну атестацію й канонічне символьне виведення на CPU або верифікованому конвеєрі FPGA.
- **Джерело:** [ch35](../../ch35-self-organizing-expert-systems-synergetics-and-npu-runtime.md), §6, три рівні апаратно-енергетичного метаболізму Edge.
- **Батьківська вимога:** REQ-L1-35-08.
- **Метод верифікації:** Аналіз.
- **Пріоритет:** P1 (Основна).
- **Статус:** Проєкт.

## REQ-L2-35-15

- **Вимога:** Експертна система повинна утримувати Edge NPU у режимі низького енергоспоживання спокою (`P_idle ≤ 3,4 Вт` для профілю `MODE_15W` при роботі передфільтра DSP `< 200 мВт`), доки символьний шлюз не пропустить вхідний вектор.
- **Джерело:** [ch35](../../ch35-self-organizing-expert-systems-synergetics-and-npu-runtime.md), §6.1, замкнений цикл розрахунку, пункт 1.

- **Вимога:** Експертна система повинна обмежувати паралелізм NPU або переносити завдання на FPGA, коли питома енергія верифікованого факту перевищує ліміт `E_verified > 15 мкДж`.
- **Джерело:** [ch35](../../ch35-self-organizing-expert-systems-synergetics-and-npu-runtime.md), §6.2, замкнений цикл розрахунку, пункт 1.

## REQ-L2-35-17

- **Вимога:** Експертна система повинна переходити в режим `Fail-Closed` при суперечливих свідченнях (`a < -0,20` і `Δ_cusp = 4a³ + 27b² ≤ 0`) і повертатися з нього лише після подолання ширини біфуркаційного гістерезису `Δb_hysteresis ≥ 4/(3√3)·(-a)^(3/2)`.
- **Джерело:** [ch35](../../ch35-self-organizing-expert-systems-synergetics-and-npu-runtime.md), §3.3.1 та закон 1 у §3.3.
- **Батьківська вимога:** REQ-L1-35-09.
- **Метод верифікації:** Тест.
- **Пріоритет:** P0 (Критична / Безпекова).
- **Статус:** Проєкт.

## REQ-L2-35-18

- **Вимога:** Експертна система повинна переходити в захисний режим `Fail-Closed` до досягнення критичної точки, коли прогноз часу до сингулярності задовольняє умову `T_TTF = t_blow - t ≤ 3·T_brake` або виконується тригер загострення `t_blow - t < 120 мс` при показнику нелінійності `β̂ > 1,00`.
- **Джерело:** [ch35](../../ch35-self-organizing-expert-systems-synergetics-and-npu-runtime.md), §3.3.3 «Режими з загостренням Курдюмова».
- **Батьківська вимога:** REQ-L1-35-09.
- **Метод верифікації:** Тест.
- **Пріоритет:** P0 (Критична / Безпекова).
- **Статус:** Проєкт.
