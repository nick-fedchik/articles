## REQ-L2-11-01

- **Вимога:** Експертна система повинна переводити знання між статусами лише в порядку: висловлювання, кандидат, підтверджений кандидат, перевірене правило, випущене знання, без пропуску жодного статусу.

- **Пріоритет:** P1 (Основна).

## REQ-L2-11-13

- **Вимога:** Експертна система повинна зберігати для кожного кандидата точкову частоту, обсяг `n`, 95-відсотковий байєсівський інтервал, його ширину `Δp`, визначену каппу Коена `κ`, ідентичність моделі/апріора та результат оцінювання окремо від допуску в baseline. Таблиця §6 застосовується в порядку: недійсні або відсутні обов'язкові входи: діагностика й `REFUSAL`; будь-який блокер `n < 10` або `Δp > 0,30` або `κ < 0,40`: `REFUSAL`; за відсутності блокерів будь-яка проміжна зона `10 ≤ n < 30` або `0,15 < Δp ≤ 0,30` або `0,40 ≤ κ < 0,75`: `QUALIFIED` з ескалацією; інакше: числові критерії виконано без автоматичного `ACCEPT`. Порогові 30 спостережень є політикою, не гарантією потрібної ширини: біля частоти 0,5 за `Beta(1,1)` орієнтир становить `n ≈ 170`; інформативний апріор потребує валідованого походження.
- **Джерело:** [ch11](../../ch11-knowledge-elicitation-from-experts.md), §6 «Математичне розмежування суб'єктивної впевненості та статистичної частоти».
- **Батьківська вимога:** REQ-L1-11-05.
- **Метод верифікації:** Тест.
- **Пріоритет:** P0 (Критична / Безпекова).
- **Статус:** Проєкт.

## REQ-L2-11-15

- **Вимога:** Експертна система повинна калібрувати суб'єктивну впевненість експертів за оцінкою Брієра (`BS ≤ 0,10` для допуску без штрафу ваги) на верифікованій історичній вибірці з контролем міжекспертної узгодженості та ширини інтервалу. Сукупний результат `n`, `Δp` і `κ` визначається впорядкованою таблицею §6 за REQ-L2-11-13; низька оцінка Брієра не скасовує блокера, не надає самостійного `ACCEPT` і не замінює погодження введення в baseline.
- **Джерело:** Попередню підставу вилучено за рішенням автора; інше першоджерело не наведено.

## REQ-L2-11-23

- **Вимога:** Експертна система повинна перед випуском правила обчислювати емпіричну втрату за визначеною шкалою та застосовувати лише поріг, установлений політикою конкретного проєкту. Якщо прийнято `τ_risk = 0,001` для бінарної частоти відмов, система повинна відхилити правило, що перевищує цей поріг; це не є нормативним порогом ASIL D і не замінює доказової оцінки.
- **Джерело:** [ch11](../../ch11-knowledge-elicitation-from-experts.md), §10 «Регламент верифікації та валідації вилучених правил», нормативний критерій релізу.

- **Статус:** Проєкт.

## REQ-L2-11-26

- **Вимога:** Підсистема опитування повинна вибирати наступне запитання за очікуваним приростом інформації і припиняти інформаційний цикл опитування, коли для всіх кандидатних запитань приріст менший за `0,05 біта`, передаючи правило на перевірку достатності безпеки (при недосягненні порогів безпеки через вичерпання інформативності запитань видається вердикт `QUALIFIED` або `REFUSAL`, але ніколи не `ACCEPT`).
- **Джерело:** [ch11](../../ch11-knowledge-elicitation-from-experts.md), §7 «Алгоритми активного опитування: максимізація інформаційного виграшу», алгоритмічне правило зупинки.

## REQ-L2-11-27
