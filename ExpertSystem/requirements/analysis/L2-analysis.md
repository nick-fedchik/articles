## 1. Критерії перевірки

Окрім критеріїв, описаних у звіті L1, для L2 додано перевірку узгодженості з батьком. Вимога L2 має уточнювати батьківську вимогу L1, а не суперечити їй.

| Код | Критерій | Ознака дефекту |
|---|---|---|
| AMBIG | Однозначність | слова-пастки без числа або без визначення («критерій корисності», «різнорідних дій», «регресія») |
| UNVERIF | Перевірюваність | немає порогу або значення, яке є в главі |
| METHOD | Відповідність методу | метод не відповідає формулюванню, наприклад поведінка з методом Інспекція |
| INCOMPLETE | Повнота | немає поведінки при порушенні, або батьківська умова пропущена |
| INFEASIBLE | Здійсненність | абсолютне значення без області чи вибірки |
| CONFLICT | Узгодженість | дві вимоги або вимога і її батько задають різні значення чи обов'язки |
| DUP | Унікальність | одна і та сама вимога повторена |
| SOURCE | Правильність | цитата або розділ не відповідає главі |
| TRACE | Простежуваність | батько існує, але тематично не відповідає вимозі |

Усі 707 батьківських посилань існують у L1-файлі тієї самої глави. Це перевірено аналітичними проходами. Незалежного скрипту не запускали.

- REQ-L2-04-02: немає відмови при неповних вхідних даних.
- REQ-L2-10-01: немає дії при відхиленні файлу (карантин, журнал).
- REQ-L2-07-04: немає поведінки при порушенні cut(P) ≤ 0,05 і коду `ERR_EXCESSIVE_GRAPH_CUT`.
- REQ-L2-16-15: append-only без винятку для видалення (глава вимагає видалення персональних даних, див. L1 K15).

- REQ-L2-23-16, REQ-L2-23-17: немає тіньового запуску перед випуском (батько L1-23-10).
- REQ-L2-26-07: немає тіньового запуску і погодження (батько L1-26-13).

### 5.4. Абсолютні значення (INFEASIBLE)

- REQ-L2-01-03: ZHR = 1,00 без вибірки і методу (див. K7 звіту L1).
- REQ-L2-08-04: Coverage R→T = 1,00 без визначеної множини R.
- REQ-L2-11-31, REQ-L2-11-36: O(1) і «жодне правило не блокує і не затримує» без вимірюваного бюджету.
- REQ-L2-11-24: нульова втрата на критичних зрізах без переліку зрізів.
- REQ-L2-22-16: «на різних процесорних архітектурах» є відкритою множиною. Глава перевіряє три платформи: x86-64, ARM64, RISC-V.
- REQ-L2-27-04: «унеможливити перефразування» перебільшено. Хеш виявляє зміну, але не запобігає їй.
- REQ-L2-32-13: «жодних об'єктів у купі» ширше за тест (`AllocsPerRun` на `LookupSubject`).

## 8. Джерельні розбіжності (SOURCE)
