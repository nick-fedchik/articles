## 1. Критерії перевірки

Кожна вимога перевірена на вісім ознак. Нижче наведено, що саме вважається дефектом.

| Код | Критерій Вігерса | Ознака дефекту |
|---|---|---|
| AMBIG | Однозначність (Unambiguous) | слова-пастки без числа: «достатньо», «належним чином», «за потреби», «гнучко», «адекватно», «у разумний строк» |
| UNVERIF | Перевірюваність (Verifiable) | немає вимірного критерію або порогу, хоча джерело його містить |
| METHOD | Відповідність методу перевірки | метод не відповідає формулюванню, наприклад поведінка з методом Інспекція |
| INCOMPLETE | Повнота (Complete) | обмеження без поведінки при порушенні або на межі |
| INFEASIBLE | Здійсненність (Feasible) | абсолютні значення (100%, нуль, «ніколи», «жодного») без області та без методу вимірювання |
| CONFLICT | Узгодженість (Consistent) | дві вимоги задають різні значення або суперечливі обов'язки для одного предмета |
| DUP | Унікальність (Necessary, without duplication) | одна вимога повторена в кількох главах |
| SOURCE | Правильність (Correct) | посилання на розділ або цитату, що не відповідає тексту глави |
| TRACE | Простежуваність (Traceable) | відсутній рядок формату або батьківського зв'язку |

Вигерсовський критерій **пріоритетності** (Prioritized) у файлах L1 не реалізовано. Жоден файл не містить поля пріоритету, тому цей критерій у звіті стоїть окремим системним зауваженням.

## 4. Дублі

Дубль означає, що одна і та сама вимога повторена в кількох главах або кількох вимогах однієї глави. Дублі не суперечать одне одному, але створюють ризик, що одна копія зміниться, а інша ні.

| Кластер | Вимоги | Пропонована дія |
|---|---|---|
| Відмова замість правдоподібної непідтвердженої відповіді | REQ-L1-01-02, REQ-L1-04-02, REQ-L1-24-04, REQ-L1-25-07, REQ-L1-28-02, REQ-L1-29-02, REQ-L1-31-03, REQ-L1-32-10, REQ-L1-40-04 | Залишити одну канонічну вимогу в ядрі, решту посилати на неї |
| Байтовий діапазон і хеш першоджерела | REQ-L1-12-01, REQ-L1-13-03, REQ-L1-15-01, REQ-L1-19-04, REQ-L1-32-06, REQ-L1-34-11, REQ-L1-36-05, REQ-L1-38-01 | Одна канонічна вимога; інші звузити до свого суб'єкта |

## 9. Системні зауваження

1. **Немає пріоритетів.** Жоден файл L1 не містить поля пріоритету. Вігерс вимагає пріоритет для кожної вимоги, щоб вирішувати конфлікти і планувати.

3. **Статус «Проєкт» без процесу затвердження.** Усі 414 вимог мають статус «Проєкт». Немає поля власника і дати перегляду.
4. **Групи 01–10 короткі.** У них по 2 вимоги на главу. Це не відповідає вимозі повного витягу.
5. **Симульовані діалоги.** Кілька глав містять вигадані репліки реальних людей. Вимоги з цих частин в L1 слід виключити або позначити як слабші. За аналізом, таких вимог у L1 небагато.
