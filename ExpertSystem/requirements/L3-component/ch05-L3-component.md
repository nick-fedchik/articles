# Компонентні вимоги рівня L3: глава 5

## REQ-L3-05-01

- **Вимога:** При завантаженні БЗ модуль перевірки повинен обчислювати SHA-256 кожного компонента першоджерела і порівнювати його з еталонним значенням. Розбіжність блокує завантаження відповідного правила.
- **Джерело:** [ch05](../../ch05-triad-of-trust-and-corporate-memory.md), §4.6.1 «Замкнений цикл побайтової кустодії доказів».
- **Батьківська вимога:** REQ-L2-05-04.
- **Метод верифікації:** Тест.
- **Статус:** Проєкт.

## REQ-L3-05-02

- **Вимога:** Оновлення БЗ повинно вимагати погодження щонайменше `k` з `n` довірених сторін за схемою розподілу секрету Шаміра (приклад: k=3, n=5). При кількості погоджень `m < k` БЗ залишається у стані `AWAITING_CONSENSUS`.
- **Джерело:** [ch05](../../ch05-triad-of-trust-and-corporate-memory.md), §5.9 «Криптографічна кустодія ключів та багатостороння авторизація змін бази знань».
- **Батьківська вимога:** REQ-L2-05-06.
- **Метод верифікації:** Тест.
- **Статус:** Проєкт.
- **Примітка:** Спосіб одержання погоджень і формування підпису потребує окремої криптографічної специфікації: схема розподілу секрету сама по собі не визначає протокол підпису чи процедуру погодження. Стан стосується оновлення; вплив на роботу попередньої версії потребує погодження.

## REQ-L3-05-03

- **Вимога:** Вивчені уроки з попередніх проєктів повинні активуватися як предикатні обмеження. Коли виявлено подібну ситуацію, експертна система повинна сигналізувати або блокувати повторення помилки.
- **Джерело:** [ch05](../../ch05-triad-of-trust-and-corporate-memory.md), §5.4 «Активні уроки».
- **Батьківська вимога:** REQ-L2-05-07.
- **Метод верифікації:** Тест.
- **Статус:** Проєкт.
- **Примітка:** Умови застосування уроку та вибір сигналу або блокування потребують погодження; саме виявлення подібності не доводить застосовності обмеження.

## REQ-L3-05-04

- **Вимога:** Компонент обліку рекомендацій повинен зберігати посилання на версії продукту, базового знімка й нормативного контексту та встановлювати позначку повторного оцінювання при зміні пов'язаної залежності.
- **Джерело:** [ch05](../../ch05-triad-of-trust-and-corporate-memory.md), §4.3 «Структура мінімального доказового запису рекомендації».
- **Батьківська вимога:** REQ-L2-05-05.
- **Метод верифікації:** Тест.
- **Статус:** Проєкт.
- **Перевірка:** Зміна пов'язаної версії продукту встановлює позначку, а зміна непов'язаного запису її не встановлює.

## REQ-L3-05-05

- **Вимога:** Компонент обліку рекомендацій повинен розрізняти відсутність рішення людини та зафіксоване рішення про прийняття, відхилення чи додатковий перегляд рекомендації.
- **Джерело:** [ch05](../../ch05-triad-of-trust-and-corporate-memory.md), §4.3, таблиця мінімального доказового запису та приклад `Recommendation`.
- **Батьківська вимога:** REQ-L2-05-01.
- **Метод верифікації:** Тест.
- **Статус:** Проєкт.
- **Перевірка:** Запис з порожнім рішенням не має статусу прийнятого; після відхилення зберігаються особа, час і підстава відхилення. Наявність полів сама по собі не засвідчує правильності рекомендації.
