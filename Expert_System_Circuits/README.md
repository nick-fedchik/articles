## Анотація

**«Схемотехніка експертних систем (СТЕС)»** — практичний інженерний підручник про те, як будувати доказові експертні системи у вигляді **скінченних ациклічних обчислювальних схем** (орієнтованих графів операційних вентилів і ліній стану), де кожний перехід від вхідного питання, вимірів, фактів і норм до відповіді є детермінованим, відтворюваним і прив'язаним до першоджерел.

На відміну від суто імовірнісної текстової генерації (LLM), яка не гарантує походження фактів і точності числових меж, та класичного необмеженого пошуку з поверненням (Prolog / загальні солвери), який втрачає передбачуваний час відгуку при розгалуженні й руйнується від першої суперечності в даних, схемотехнічний підхід розділяє систему на три інженерні ешелони:

1. **Ешелон 1 — Високорівневий граф міркування ([`src/reason`](src/reason/reason.go)):** прямий багатоступеневий прогноз наслідків (`Forecast`), перевірка тверджень (`Whether`) і зворотна діагностика причин з вибором наступної перевірки (`Why`) над чотиризначними станами свідчень Белнапа та множинами першоджерел без подвійного обліку.
2. **Ешелон 2 — Компіляція, чисті доведення та верифікований шлюз допуску ([`src/clean.go`](src/clean.go), [`src/normative.go`](src/normative.go), [`src/kernel`](src/kernel/kernel.go), [`src/formal/kernel/Kernel.lean`](src/formal/kernel/Kernel.lean)):** двопрохідне виділення чистих доведень (`CleanProof`) у графах зі суперечностями, розв'язання нормативних винятків (*lex specialis*), зворотний пошук безпечних ремонтів (`FindRepair`) та механізовано доведений у Lean 4 шлюз допуску дії.
3. **Ешелон 3 — Безцикловий асемблер EPU та апаратний компаратор на ПЛІС ([`src/hardware`](src/hardware/README.md), [`src/rtl/gate`](src/rtl/gate/README.md)):** трансляція ациклічних гілок у потік регістрових інструкцій із переходами тільки вперед (`forward-only jumps`), липкими прапорцями порушень і синтезованим на `iCE40HX8K` однотактовим компаратором на деревах збереження переносу (`csa64`, частота **`104,50–110,57 МГц`**).

Кожна формула, таблиця та алгоритм у цьому підручнику відповідає реальному виконуваному коду, тестам і синтезованим схемам у каталозі [`src/`](src/README.md).

## 3. Швидкий старт і команди перевірки всіх глав

Усі програмні приклади, еталонні розрахунки та тести підручника виконуються стандартним інструментарієм Go без зовнішніх залежностей із каталогу [`src/`](src/README.md):

```sh
cd src

# Повна перевірка всіх пакетів із детектором гонитви даних:
go test -race ./...
go vet ./...

# Глава 3 — траси високорівневих схем діагностики (випадок 1) та прогнозу поставок (випадок 2):
go run ./cmd/reason -case 1 -scenario S1
go run ./cmd/reason -case 2 -scenario S1

# Глава 6 — приклад і порівняльний стенд шлюзу допуску:
go run ./cmd/kernel
go test -race -count=1 ./kernel ./baseline

# Глава 7 — апаратний сайзинг слів/BRAM та генерація тестових векторів RTL:
go run ./cmd/hardware -states=4096 -bus-bits=64 -hz=100000000 -leaves=1024
go test -race -count=1 ./hardware ./cmd/gatevectors
```
