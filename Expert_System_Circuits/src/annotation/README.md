# Протокол незалежного анотування та оцінювання

## 1. Призначення та невиконана частина

Для перевірки природномовного входу доказової експертної системи потрібні зовнішні мітки, а не відповідність моделі її ж навчальним прикладам. Цей пакет готує локальний процес подвійного анотування, арбітражу та оцінювання. **Новий незалежний людський корпус не створено.** Вбудований приклад згенеровано програмою; він перевіряє інструмент, не якість розуміння норм.

Доступні лише стандартна бібліотека Go та [наявний обчислювач інтервалу Вілсона](../corpus.go). Мережевих запитів, завантаження джерел або автоматичного надсилання даних немає. Приватні корпуси слід зберігати поза публічним репозиторієм; дозвіл на використання джерела перевіряє відповідальна людина, не прапорець JSON.

## 2. Склад корпусу та одиниця розбиття

Формат `ect.annotation.v1` описано [Go-типами](model.go). Назви JSON-полів відповідають експортованим полям типів.

1. `Corpus`: `Schema`, `ID`, `Guidelines`, `Synthetic`, `Documents`, `Items`. Інструкція `Guidelines` повинна фіксувати одиницю анотування, словник канонічних ролей, модальності, правила розмітки умов/винятків/заперечення й необхідний контекст. Вона включається до відбитка корпусу.
2. `Document`: `ID`, `Family`, `Version`, `SHA256`, `Language`, `Access`. `Access` — `public`, `permission` або `private`. Геш повного документа декларує постачальник: утиліта не має його байтів і не перевіряє їх автоматично.
3. `Item`: `ID`, `DocumentID`, `Task`, `Text`, `TextSHA256`, `Question`. SHA-256 **точних UTF-8-байтів тексту** перевіряється. Для `extract` запит порожній; для `decision` явний запит обов'язковий. Весь потрібний для рішення контекст має міститися в тексті одиниці; прихованого звернення до інших документів немає.
4. `Family` об'єднує версії, переклади та похідні джерела. Пов'язані явними пріоритетами одиниці також мають залишатися в одній сім'ї. Це предметна декларація, не автоматично доведена незалежність документів.
5. Розбиття детерміноване за SHA-256 від seed і сім'ї. Для щонайменше трьох сімей виділяється не менше однієї на `test` і `calibration`; решта — `train`. При великих наборах частки сімей наближаються до 20/20/60, але **кількість рядків і класи не балансуються**.
6. Повтори тексту після зведення регістру й пробілів відхиляються з ідентифікаторами обох одиниць; однаковий геш документа не може належати різним сім'ям. Утиліта не видаляє повтори мовчки й не виявляє довільні семантичні перекази. Причину повтору має розглянути людина.

Корпус обмежено 10 000 документів, 100 000 одиниць, 1 МіБ на текст та 64 МіБ сумарного тексту з інструкціями й запитами. JSON-файл CLI також обмежено 64 МіБ, вкладеність — 64 рівнями; невідомі й дубльовані без урахування регістру ключі відхиляються.

## 3. Мітки, сліпота та арбітраж

Мітка видобування має `Kind`: `NORM`, `FACT` або `NO_ATOM`. Для `NORM` допустимі `OBLIGATION`, `PROHIBITION`, `PERMISSION`, `RECOMMENDATION`. Для норми й факту потрібні `Actor`, `Action`, `Target`: кожна роль містить канонічне `Value` та опорний `Span`. Формат v1 призначений для виразних трирольових фрагментів; це не повна мова природномовних вимог.

`Span` — напіввідкритий інтервал `[Start, End)` **у байтах**, а не символах. Межі повинні припадати на межі UTF-8-кодів. Окремі масиви фіксують `Conditions`, `Exceptions`, `Negations`, `Evidence`; `PriorityOver` містить явні ID інших нормативних одиниць. `Parameters` задає змінну, відношення `<`, `<=`, `>`, `>=`, `==`, точний десятковий дріб або раціональне число без експоненти, одиницю й опорний фрагмент. Перетворення одиниць і перевірки правильності людської канонізації немає.

Для `NO_ATOM` потрібне пояснення `Rationale`, без вигаданих ролей. Відсутність відповідного формату **не означає** відсутності факту чи норми: нерепрезентований випадок слід залишити чернеткою та уточнити схему/обсяг до фіксації оцінювання, а не примусово записувати як `NO_ATOM`.

Для `decision` мітка `Kind=DECISION` містить один із чинних вердиктів `ALLOW`, `DENY`, `DEFER_UNKNOWN`, `DEFER_CONFLICT`, `DEFER_NO_BASIS`, пояснення та опорні `Evidence`. Тільки для `DEFER_NO_BASIS` дозволено не мати опорного фрагмента. Додаткової логіки суперечливого походження цей пакет не вводить.

Порядок роботи:

1. Два різні анотатори отримують корпус та **окремі порожні шаблони**, без золотих міток, чужих відповідей і передбачень моделі.
2. Кожний незалежно заповнює всі записи, ідентифікатор, `Human`, `Blind`, `ModelAssisted`; завершений файл має `Status=submitted`. Чернетки не зараховуються як дані.
3. Порівняння звітує повний структурний збіг і окремі збіги класу/модальності, ролей, умов, винятків, заперечення, пріоритетів, параметрів, рішень. Порядок множинних фрагментів не впливає; вільний текст пояснення не створює структурної розбіжності. За повного збігу для золотої мітки зберігається пояснення першого анотатора; обидва оригінали залишаються у вхідних файлах.
4. Cohen κ обчислюється лише для категорії «клас + модальність» видобування, не для всього структурного запису. Вироджені маргінальні розподіли або відсутність таких завдань дають `null` із поясненням, а не удавану одиничну узгодженість.
5. Окремий арбітр подає `Resolutions` рівно для всіх розбіжностей. Зайві, відсутні чи дубльовані записи є помилкою. Зміна вже узгоджених даних потребує нової версії процесу, а не прихованого виправлення.
6. Для несинтетичного корпусу збирання золотої розмітки потребує заявлених сліпих людських анотацій без модельної допомоги та окремого людського арбітра. Зберігаються SHA-256 структурованих вхідних файлів.

**`IndependenceAttested` — лише узгоджена декларація метаданих.** Програма не перевіряє особу, відсутність змови, фактичну сліпоту чи використання ШІ. Псевдоніми однієї людини не створюють незалежності. Для синтетичного прикладу цей прапорець завжди хибний.

## 4. Оцінювання та знаменники ризику

План розбиття й його відбиток потрібно зафіксувати до навчання; пороги вибираються тільки на `calibration`. Утиліта не може довести хронологію цих дій. Оцінка за замовчуванням стосується лише `test`, перевіряє сімейства й повноту плану. Звіт містить відбитки корпусу, плану та золотих міток.

Для **кожної** одиниці обраного розбиття потрібен рівно один `Prediction`: або `Abstain=true` без мітки, або повна `Label` з `Abstain=false`. Відсутній запис не прирівнюється до відмови; записи іншого розбиття відхиляються.

- `ExtractionExact` і `DecisionExact` мають власні кількості збігів/оцінених **неутриманих** записів; поруч наведено кількість завдань кожного типу й утримань.
- `ExtractionFields` окремо порівнює клас/модальність, ролі, умови, винятки, заперечення, пріоритети й числові параметри. Кожне поле має власний знаменник.
- Покриття автоматичних рішень — `AutomaticDecisions / DecisionItems`. `ALLOW` і `DENY` автоматичні; усі `DEFER_*` і явні утримання неавтоматичні.
- `FalseAllow` — частка неправильних `ALLOW` **серед виданих ALLOW**; золоте `DEFER_*` не дозволяє автоматичного схвалення.
- `FalseDeny` — частка неправильних `DENY` **серед виданих DENY**. Це не класична частота false positive із знаменником «усі справді негативні».
- `AutomaticRisk` — усі неправильні автоматичні рішення серед усіх автоматичних рішень.
- При нульовому знаменнику межі ризику — `null` із поясненням. Нуль відповідей не означає нульового виміряного ризику.
- `FalseNormFromNoAtom` окремо рахує вигадування нормативного атома для золотого `NO_ATOM`.

Для ненульових знаменників наведено 95-відсоткові інтервали Вілсона. Вони передбачають незалежні біноміальні випробування; корельовані одиниці одного документа цього не гарантують. Інтервали слід читати як описову умовну оцінку, не сертифікат популяційного ризику. Немає автоматично дозволеної робочої точки чи промислової гарантії.

## 5. Команди відтворення

Команди запускаються з [кореня Go-модуля](../README.md). Шляхи `LOCAL_*` означають явні локальні файли користувача, не джерела, додані до книги:

```sh
go test ./annotation ./cmd/annotate
go run ./cmd/annotate demo
go run ./cmd/annotate prepare -corpus LOCAL_CORPUS.json -out NEW_PACKET_DIRECTORY -seed 42
go run ./cmd/annotate validate -corpus LOCAL_CORPUS.json -annotation LOCAL_A.json
go run ./cmd/annotate compare -corpus LOCAL_CORPUS.json -a LOCAL_A.json -b LOCAL_B.json
go run ./cmd/annotate adjudicate -corpus LOCAL_CORPUS.json -a LOCAL_A.json -b LOCAL_B.json -arbiter LOCAL_ARBITRATION.json -out NEW_GOLD.json
go run ./cmd/annotate evaluate -corpus LOCAL_CORPUS.json -plan LOCAL_SPLIT.json -gold LOCAL_GOLD.json -predictions LOCAL_PREDICTIONS.json -split test
```

`prepare` створює лише `split.json` і два незаповнені шаблони. `demo` виводить явно синтетичний самотест; він не створює людських міток. Вихідні файли створюються з правами `0600` та виключним створенням, без перезапису наявної роботи. У разі помилки запису команда завершується з помилкою; частково створені файли не вважаються завершеним пакетом.

[Тести пакета](workflow_test.go) перевіряють витік між сім'ями, повтори, UTF-8-межі, підміну відбитків, відсутні прогнози, арбітраж, нульові знаменники та помилкові дозволи. [CLI-тести](../cmd/annotate/main_test.go) виконують повний синтетичний процес із тимчасовими файлами й перевіряють заборону перезапису. Це інженерна перевірка інструмента; фактичне незалежне анотування залишається невиконаним.
