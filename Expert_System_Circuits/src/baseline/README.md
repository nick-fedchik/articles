# Порівняння шлюзу ядра K з базовими рішеннями (H3) та інжекція помилок (H4)

Пакет виконує гіпотези H3 і H4 попередньо зареєстрованого протоколу [`PREREGISTRATION-2026-11-03.md`](../PREREGISTRATION-2026-11-03.md). Він не змінює ядро [`kernel`](../kernel) і порівнює його з наївним та звичайним інженерним шлюзом допуску на тому самому синтетичному безпековому випадку. Аналіз підготовлено за участі ШІ без фахівця предметної галузі, тому він перевіряє інженерну логіку, а не є галузевою валідацією.

## 1. Навчальний випадок і чотири плечі

LLM-агент пропонує дію `open_admission_valve` — подачу газу в посудину. Дія фізично безпечна, якщо істинний поточний тиск лежить у жорсткому вікні $[0, 8]$ бар, оператор авторизований, є процесний запит, немає блокування обслуговування й інтерлока, а вогневі роботи покриті пройденим газотестом. Окрім семи задіяних у правилах і захисних умовах атомів (`0..6`), специфікація [`CaseSpec`](case.go) містить восьмий незадіяний телеметричний атом `AtomUnreferencedNoise` (`unreferenced_telemetry`), який не входить до жодної захисної умови, правила виведення чи норми. Це дозволяє безпосередньо перевірити стійкість шлюзу до засмічення вхідного знімка сторонніми фактами (`F11_UNREFERENCED_SPAM`, зауваження F-01) та блокування виведень, що спираються на суперечливі свідчення `BOTH` (`Clean`, теорема B.7, зауваження F-02).

| Плече | Інформація | Рішення |
| --- | --- | --- |
| A | скалярна впевненість на факт (noisy-OR надійностей джерел), середина інтервалу як число в барах | плаский ланцюг «спочатку заборони», без свіжості й походження |
| B0 | точкове значення з одиницею, один boolean на факт, журнал походження лише для аудиту | типізовані одиниці, запас похибки 0.3 бар, двостороння свіжість усіх отриманих прапорців, Horn-замикання, правила за порядком |
| B1 | ті самі метадані, що й у C: інтервали, про/контра, джерела, мітки часу, винятки й пріоритети | той самий стек, написаний з обмежень SC-1…SC-9 для задіяних атомів, з перетворенням одиниць |
| C | ті самі метадані | `kernel.Evaluate` над [`CaseSpec`](case.go) (область `relevantAtom` та чиста підтримка `Clean`) |

Варіант B1S (B1 без перетворення одиниць) — розвідувальний аналіз чутливості, його не було в протоколі.

## 2. Відтворення

```sh
go test -race ./baseline ./cmd/baseline
go run ./cmd/baseline -out testdata/baseline           # детерміновані результати
go run ./cmd/baseline -out testdata/baseline -timing   # також timing.csv
```

Сід PCG 20261103; 1000 інжектованих сценаріїв і 250 зіставлених чистих контролів на кожен клас помилок, 1000 сценаріїв класу `CLEAN` (разом $14\,750$ сценаріїв у межах моделі та $1\,250$ сценаріїв поза моделлю `X11`). Файли `results.json`, `results.csv` і `scenarios.csv` детерміновані; `timing.csv` містить мікробенчмарк хоста й не детермінований.

## 4. Стратифікація статистичних меж (H4, зауваження F-08)

Зведення всіх 11 інжектованих класів у межах моделі в один пул без стратифікації змішує два якісно різні режими роботи шлюзу C:

1. **Дев'ять класів повної відмови (`Allow == 0`):** `F01_STALE`, `F02_UNIT`, `F03_STRADDLE`, `F04_CONTRARY`, `F05_EXCEPTION_UNKNOWN`, `F06_UNTRUSTED_PROVENANCE`, `F08_LLM_UNSUPPORTED`, `F09_DUPLICATED_SOURCES`, `F10_CLOCK_FUTURE`. У кожному з цих класів інжектована помилка порушує принаймні одну обов'язкову передумову $P$ на релевантному атомі чи вимірюванні, тому плече C детерміновано відхиляє всі 1000 сценаріїв (`Allow = 0`). Умовний ризик небезпечного дозволу серед виданих дозволів `UnsafePhysPerAllow` має нульовий знаменник (`Undefined (0/0)`, поле `Defined: false` у `results.json`). Ці класи коректно оцінюються безумовною верхньою межею на сценарій (`UnsafePhysPerScenario`): $0 / 1000$ на клас (двостороння 95% межа Клоппера — Пірсона $0.003682$, одностороння $0.002991$, правило трьох $0.003000$) та $0 / 9000$ сукупно (двостороння 95% межа Клоппера — Пірсона $0.000410$).
2. **Два класи з активними дозволами (`Allow > 0`):** `F07_NORM_PRIORITY_CONFLICT` (`Allow = 196`, двостороння 95% межа Клоппера — Пірсона на дозвіл $0.018645$) та `F11_UNREFERENCED_SPAM` (`Allow = 435`, двостороння 95% межа Клоппера — Пірсона на дозвіл $0.008444$). Сукупно на активних інжектованих класах ядро C видає `Allow = 631` із `0` небезпечних дозволів (двостороння 95% межа Клоппера — Пірсона на дозвіл $0.005829$, одностороння $0.004736$, правило трьох $0.004754$; на сценарій $0 / 2000 \to 0.001843$). Разом із чистими контролями та класом `CLEAN` (`Allow = 446`) загальна кількість дозволів у межах моделі становить `Allow = 2058` на $14\,750$ сценаріїв (двостороння 95% межа Клоппера — Пірсона на дозвіл $0.001791$, на сценарій $0.000250$).

## 5. Розмір специфікації та спільна довірена база (TCB, зауваження F-06)

Функція `SpecLines` рахує лише рядки правил конкретного випадку між маркерами `// spec:<arm>:begin` і `// spec:<arm>:end` (без порожніх рядків і коментарів), а `SharedEngineLines` окремо фіксує обсяг спільного рушія та допоміжного коду:

| Компонент | Рядків коду (SLOC без коментарів) | Призначення |
| --- | --- | --- |
| `SpecLines["A"]` | 13 | імперативний ланцюг порівнянь плеча A |
| `SpecLines["B0"]` | 39 | імперативна логіка й таблиця правил плеча B0 |
| `SpecLines["B1"]` | 79 | імперативна реалізація обмежень SC-1…SC-9 плеча B1 |
| `SpecLines["C"]` | 35 | декларативна специфікація `CaseSpec` для ядра C |
| `conventional_units` (`units.go`) | 27 | типізовані одиниці тиску та конвертація для B0/B1 |
| `conventional_support` (`arm_b.go` поза маркерами) | 140 | проєкція, журнал аудиту SHA-256 та обгортки Horn-замикання |
| `kernel_evaluate` (`kernel.go`) | 365 | компіляція й обчислення `kernel.Evaluate` (включно з `relevantAtom` і `Clean`) |
| `kernel_verify` (`verify.go`) | 273 | незалежний перевірник сертифіката `kernel.Verify` |
| `kernel_safety` (`safety.go`) | 127 | пряма перевірка властивості безпеки `kernel.CheckSafety` |
| `kernel_total` | 765 | сукупний обсяг пакету `kernel` (оцінювач + перевірник + предикат безпеки) |

Отже, менший розмір `SpecLines["C"] = 35` порівняно з `SpecLines["B1"] = 79` відображає перехід від імперативного кодування перевірок до декларативного опису теорії, який спирається на повторно використовуваний рушій `kernel` (365 SLOC для `Evaluate` та 273 SLOC для `Verify`).

## 6. Обмеження

1. Для C критерій $P$ є круговим: ядро допускає дію тоді й лише тоді, коли виконується $P$.
2. Фізична істина залежить від припущень генератора: довірені джерела чесні, а чесний інтервал містить істину. Клас `X11_OOM_TRUSTED_BIAS` показує, що за порушення цих припущень помиляються всі плечі (`196` фізично небезпечних дозволів із `519` дозволів у B1 та C).
3. Сценарії одного класу не є незалежними реальними випробуваннями, тому межі описують лише синтетичний генератор.
