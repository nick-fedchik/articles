# Механізована перевірка ядра K шлюзу допуску СТЕС

Цей каталог містить абстрактну модель ядра $K$ із пакета `src/kernel` і доведення її наскрізної коректності в Lean 4. Модель потрібна, щоб перевірити не окремий приклад, а логіку вердикту `ALLOW` для будь-яких скінченних специфікацій і вхідних знімків.

## Що доведено

Файл [`Kernel.lean`](Kernel.lean) не містить `sorry`. Головні теореми:

1. `soundness`: якщо специфікація `S` є добре сформованою (`WellFormed S`, включно з топологічною ациклічністю `Acyclic S`), перевірник сертифіката за рівняннями нерухомої точки приймає сертифікат (`verifyCert S I c = true`), і `c.verdict = .allow`, то виконується властивість безпеки `P S I`.
2. `allow_iff_P`: `verdict S I = .allow` тоді й лише тоді, коли виконується `P S I`. Окрема передумова про впорядкованість вимірів не потрібна: `P4` сам вимагає `m.lo ≤ m.hi`, а `guardState` відображає перевернутий інтервал у `U`.
3. `allow_prohibitions_defeated_by_permit` і `soundness_permit`: якщо пріоритети утворюють строгий порядок (`StrictOrd S.dom`), кожну застосовну заборону перемагає застосовний дозвіл (`P2permit`); `soundness_permit` поєднує це з `soundness` для прийнятого сертифіката.
4. `fixpoint_closure_unique`, `fixpoint_clean_unique`, `verifyCert_unique` і `evaluate_verifies`: для ациклічної знакової теорії Хорна рівняння нерухомої точки на `0 .. S.atoms - 1` однозначно визначають як найменше знакове замикання `closure`, так і чисту підтримку `clean` (теорема B.7), тому `verifyCert` приймає сертифікат `evaluate S I` і узгоджується з ним на всіх атомах і полях вердикту.

Властивість `P` складається з шести пунктів:

1. `P1`: існує дозвіл, усі умови якого мають значення `TRUE` у замиканні та чисту підтримку в `clean` (виведення без спирання на суперечливі предки `BOTH`, теорема B.7), виняток має значення `FALSE`, і жодне застосовне правило не стоїть вище за нього.
2. `P2`: кожну застосовну заборону строго домінує застосовне правило (а за строгого порядку пріоритетів `StrictOrd` — застосовний дозвіл, що також перевіряє `CheckSafety` у `safety.go`).
3. `P3`: жодна умова чи виняток не мають значень `UNKNOWN` або `BOTH`.
4. `P4`: кожен вимірюваний інтервал має одиницю захисної умови, впорядковані межі (`lo ≤ hi`) і лежить у межах замкненого вікна допуску. У Go перевернутий інтервал відхиляє `validateInput` ще до обчислення вердикту.
5. `P5`: вік кожного релевантного факту (`relevantAtom S a = true`, тобто атома, задіяного в захисних умовах, правилах свідчень або нормах) та кожного вимірювання лежить у межах від нуля до `MaxAge`. Незадіяні шумові факти на сторонніх атомах не блокують допуск.
6. `P6`: кожен релевантний факт і кожне вимірювання має непорожню множину джерел, яка входить до множини перевірених.

## Межі моделі та спільна довірена база (TCB)

Теореми стосуються лише цієї моделі. Відповідність Go-пакета `src/kernel` моделі не механізовано (немає екстракції коду чи доведення уточнення); її підтримують лише тести та обмежений перебір `kernel.Exhaustive`. Модель механізує алгоритм ядра та рівняння сертифіката:

1. Числа подано типом `Int`. Реалізація на Go використовує скінченні `float64` і лише операції порівняння. Джерела подано натуральними номерами, у Go — рядками; дайджести SHA-256 і серіалізацію не змодельовано.
2. Замикання свідчень (`closure`) та чиста підтримка (`clean`, теорема B.7) задані явно через скінченний список знакових правил `evid : List EvRule`. Перевірник `verifyCert` перевіряє декларативні рівняння нерухомої точки `stepClosureAtom` та `stepCleanAtom` для кожного атома `a < S.atoms`, а теореми `fixpoint_closure_unique` і `fixpoint_clean_unique` доводять, що за умови `Acyclic S` розв'язок цих рівнянь єдиний і збігається з топологічним проходом `evaluate`.
3. Пріоритет `dom` є довільним булевим відношенням для базової теореми `soundness` та строгим порядком `StrictOrd` для теореми `allow_prohibitions_defeated_by_permit` (у Go компілятор `CompileNormative` будує транзитивне замикання й відхиляє цикли).
4. **Спільна довірена база (Shared TCB) між `Evaluate` і `Verify` у Go:** обидві функції спільно використовують статичний компілятор теорії `compile(s)` (`validateSpec` + `evidence.CompileNormative`) та перевірник нормативної політики `NormProgram.Verify` (який перевіряє статуси правил і дайджести SHA-256). Усі динамічні обчислення ядра — початкові стани атомів і захисних інтервалів, найменше знакове замикання `leastClosure`, найменша нерухома точка чистої підтримки `leastClean`, перевірка свіжості через `big.Int`, перевірка джерел для релевантних атомів і пониження вердикту — обчислюються у `verify.go` незалежно від `Evaluate`.

## Відтворення

Lean встановлено локально без системних змін. Перевірено версії:

- `elan 4.2.4`: архів `elan-x86_64-unknown-linux-gnu.tar.gz`, SHA-256 `42b94d4244e8353142c456ec0e4ca6528fd898a6c604d4059f494e706e431f63`; хеш збігається з дайджестом активу GitHub release v4.2.4;
- `Lean 4.35.0`, коміт `eb6cafb7290e8bd5f2937522d8d804f58f02bafc`; версію закріплено у [`lean-toolchain`](lean-toolchain);
- бібліотеку Mathlib не використано.

```sh
mkdir -p ~/.local/elan-dl ~/.local/elan-tmp && cd ~/.local/elan-dl
curl -sSfL -o elan.tar.gz https://github.com/leanprover/elan/releases/download/v4.2.4/elan-x86_64-unknown-linux-gnu.tar.gz
sha256sum elan.tar.gz   # 42b94d42...431f63
tar xzf elan.tar.gz
ELAN_HOME=~/.local/elan TMPDIR=~/.local/elan-tmp ./elan-init -y --no-modify-path --default-toolchain leanprover/lean4:v4.35.0

cd Expert_System_Circuits/src/formal/kernel
ELAN_HOME=~/.local/elan ~/.local/elan/bin/lean Kernel.lean          # без виводу, код 0
(cat Kernel.lean; echo '#print axioms GateKernel.soundness') | \
  ELAN_HOME=~/.local/elan ~/.local/elan/bin/lean --stdin
# 'GateKernel.soundness' depends on axioms: [propext, Classical.choice, Quot.sound]
```

Окрема перевірка Go-реалізації:

```sh
cd Expert_System_Circuits/src
go test ./kernel -race
go run ./cmd/kernel -mode exhaustive -norms 2 -conditions 1 -exceptions
```
