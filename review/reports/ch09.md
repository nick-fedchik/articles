## Findings and Corrections

### R09-01: Coverage accepted a PASS without exercised implementation

**Old quote:** `\neg\exists\,t\in V_T,\ e\in V_E:\ t\xrightarrow{\mathrm{verifies}}r\ \land\ e\xrightarrow{\mathrm{produced\_by}}t\ \land\ \mathrm{verdict}(e)=\mathrm{PASS}\ \land\ \mathrm{release}(e)=\rho`

**New quote:** `\neg\exists\,t\in V_T,\ e\in V_E,\ c\in V_C:\ t\xrightarrow{\mathrm{verifies}}r\ \land\ t\xrightarrow{\mathrm{exercises}}c\ \land\ c\xrightarrow{\mathrm{satisfies}}r\ \land\ e\xrightarrow{\mathrm{produced\_by}}t\ \land\ \mathrm{verdict}(e)=\mathrm{PASS}\ \land\ \mathrm{release}(e)=\rho`

**Derivation:** §3.3 distinguishes declared `verifies` from measured `exercises`. The old witness lacked any requirement that the passing test exercise code satisfying the same requirement.

**Reader consequence:** A graph with `satisfies(c,r)`, `verifies(t,r)`, and a PASS run, but no `exercises(t,c)`, remains uncovered. This prevents a passing but unrelated test from inflating release coverage; the example remains `1 - 2/150 = 148/150 ≈ 0.9867`. The edge table, authorial invariant, registry S04-01, REQ-L2-09-03, REQ-L3-09-32, and REQ-L3-09-40 now state the same rule.

### R09-02: PASS evidence had no release identity

**Old quote:** `+String run_id`, `+Timestamp timestamp`, `+String verdict`, `+Float coverage_mcdc`, `+String signature`.

**New quote:** `+String target_release_id`; §3.3 now says: “Цей ідентифікатор має однозначно вказувати на код або образ, що перевірявся; запуск з іншим ідентифікатором не зараховується для випуску $`\rho`$.”

**Derivation:** The coverage predicate required `release(e)=rho`, but the declared evidence fields did not expose a release identity.

**Reader consequence:** The model now carries the identity needed to distinguish a current PASS from a stale run. It does not prescribe a release-signing or artifact-manifest protocol. REQ-L3-09-08 and REQ-L3-09-32 now require this field.

### R09-03: Closed-world prose treated incomplete data as proof of absence

**Old quote:** “В інженерії функціональної безпеки відсутність тесту означає неприпустиму відмову: порушення інваріанта покриття $`\mathrm{Coverage}_{R \rightarrow T} = 1.0`$, що негайно блокує збирання релізу в CI/CD.”

**New quote:** “Для випуску з оголошеним і перевіреним повним зрізом вимог відсутність залікового ланцюга означає непокриту вимогу й за описаним шлюзом блокує випуск. Якщо повноту джерел або зрізу не підтверджено, відсутність ребра лишається невідомістю”.

**Derivation:** §4.1 and the requirements already state that absence in an incomplete slice is unknown; the modeled response omitted that precondition.

**Reader consequence:** Closed-world reasoning is limited to a verified complete slice. The gate response when completeness is unknown remains open rather than being silently invented.

### R09-04: Unmeasured complexity, latency, completeness, and regulatory guarantees

**Old quotes:** “...не забезпечує детермінованого часу запиту $O(1)$...” ; “Всі транзитивні шляхи замикання обчислюються локально за мілісекунди...” ; “...за лічені мілісекунди... гарантуючи математичну повноту аудиторського сліду” ; “...за частки секунди будує транзитивне замикання...”. The modeled author also said: “Вони вимагатимуть юридично неспростовного доказу”.

**New quotes:** “...у цій главі не виміряні”; “...у цій главі їх не виміряно й не доведено”; “Числа й перелік є ілюстративними, а не результатами вимірювання”; and “конкретні очікування залежать від системи, юрисдикції та застосовної основи сертифікації”.

**Derivation:** The chapter supplies no graph-size bound, WCET analysis, benchmark, or external regulatory source for these assertions. A local snapshot does not imply constant-time transitive closure or measured latency.

**Reader consequence:** The local-snapshot and impact-analysis proposals remain, without implying universal performance, impact completeness, or regulator requirements. Registry S08-02–05 is aligned, and the simulated-dialogue disclaimer remains intact.
